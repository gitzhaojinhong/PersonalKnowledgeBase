## 聚合概述

### 聚合分类

Elasticsearch 聚合（Aggregation）分为三大类，相互之间可嵌套组合：

| 分类 | 标识 | 职责 | 典型场景 |
|------|------|------|----------|
| **Bucket** | 分桶 | 将文档按条件分配到不同"桶"中，每个桶包含一组文档 | 按标签分组、按时间区间分片、按地域划分 |
| **Metric** | 指标 | 对文档集合进行统计计算，输出数值结果 | 平均值、求和、去重计数、百分位 |
| **Pipeline** | 管道 | 对已有聚合结果进行二次加工，输入来自其他聚合 | 环比增长、移动平均、累计求和 |

**关键原则**：Bucket 决定"范围"，Metric 决定"算什么"，Pipeline 决定"怎么再算"。一个聚合查询中可同时包含多类聚合，通过 `aggs` 嵌套实现"先分桶再算指标"的级联语义。

### 聚合结构

聚合在请求体中以 `aggs`（或 `aggregations`）为根节点，通过嵌套字典定义层级关系。基本骨架如下：

```json
{
  "size": 0,
  "aggs": {
    "<agg_name>": {
      "<agg_type>": { "<params>": "..." },
      "aggs": { "<sub_agg_name>": { "..." } }
    }
  }
}
```

| 结构要素 | 说明 |
|----------|------|
| `size: 0` | 不返回命中文档，仅返回聚合结果（非必须但强烈推荐） |
| `agg_name` | 用户自定义聚合名称，在结果中用于取值 |
| `agg_type` | 聚合类型关键字（`terms`、`avg`、`date_histogram` 等） |
| 嵌套 `aggs` | 子聚合，在当前桶的上下文中执行 |
| 同级聚合 | 可在同一层级定义多个聚合，互不影响 |

**常见嵌套模式**：

```
terms (分桶) ──┐
               ├── avg (子指标)
               ├── sum (子指标)
               └── date_histogram (子分桶) ── avg (孙指标)
```

### 与 SQL GROUP BY 对比

| 维度 | SQL GROUP BY | ES Aggregation |
|------|--------------|----------------|
| 分组字段 | `GROUP BY field` | `terms` / `date_histogram` 等 Bucket 聚合 |
| 聚合函数 | `COUNT(*)`、`AVG(field)`、`SUM(field)` | Metric 聚合：`value_count`、`avg`、`sum` |
| 多级分组 | `GROUP BY a, b` 或子查询嵌套 | 嵌套 `aggs`（无限层级） |
| HAVING | `HAVING avg > 100` | `bucket_selector` Pipeline 聚合 |
| ORDER BY | `ORDER BY count DESC` | `terms` 的 `order` 参数 / `bucket_sort` |
| LIMIT | `LIMIT 10` | `size` 参数或 `bucket_sort` |
| 窗口函数 | `ROW_NUMBER() OVER(...)` | `bucket_sort` + `from` 分页 |
| 数据源 | 表行数据 | 倒排索引 + doc_values |

**核心差异**：

- SQL 是"先过滤再分组再聚合"，ES 是"先过滤再分桶再指标计算"，但 ES 的 Bucket 可以不依赖全局排序。
- ES 的 `terms` 聚合是近似的（基于 shard 级 Top N 合并），默认 `size=10` 且不保证精确。这是与 SQL 最本质的不同。
- ES 支持嵌套聚合深度无限制，而 SQL 子查询嵌套受限于 SQL 语义。

## Bucket 聚合

### terms

**概念**：对指定字段的值进行分组，统计每个值出现的文档数量（类似 SQL 的 `GROUP BY`）。默认基于 shard 级 Top N 合并，**在数据量较大时结果是近似的**。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `field` | string | — | 目标字段（需为 keyword 或启用 `fielddata` 的 text） |
| `size` | int | 10 | 返回的桶数量上限 |
| `shard_size` | int | `size * 1.5 + 10` | 每个 shard 返回的桶数量，提升可改善精度 |
| `min_doc_count` | int | 1 | 最小文档数阈值，低于此值的桶不返回 |
| `show_term_doc_count_error` | bool | false | 是否展示文档计数误差 |
| `order` | object | `{"_count": "desc"}` | 排序规则，支持 `_count`、`_key` 或子聚合指标 |
| `missing` | string | — | 缺失值填充，空值文档归入此桶 |
| `include` / `exclude` | string[] | — | 正则过滤桶的值（支持正则或数组） |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/orders/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "by_status": {
      "terms": {
        "field": "status.keyword",
        "size": 20,
        "shard_size": 40,
        "min_doc_count": 5,
        "show_term_doc_count_error": true,
        "order": { "_count": "desc" }
      },
      "aggs": {
        "avg_amount": {
          "avg": { "field": "total_amount" }
        }
      }
    }
  }
}'
```

**注意事项**：

- 对 `text` 类型字段需使用 `.keyword` 子字段，否则需开启 `fielddata=true`（不推荐，内存开销大）。
- `size` 增大时精度提升但性能下降。如需精确计数，组合使用 `cardinality` 聚合或借助 `composite` 聚合分页。
- 高基数字段（如 UUID）慎用 `terms`，桶数量爆炸会导致内存压力。
- `shard_size` 建议设为 `size * 2` 起步，最高可设到 `size * 10`。

### range

**概念**：按用户自定义的数值区间对文档分桶。每个区间由 `from` 和 `to` 定义，区间左闭右开（`[from, to)`）。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `field` | string | — | 数值型字段 |
| `ranges` | array | — | 区间定义数组，每项含 `key`(标签)、`from`(含)、`to`(不含) |
| `keyed` | bool | false | 是否以区间 key 为键返回（而非数组） |
| `missing` | number | — | 缺失值归入的数值 |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/products/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "price_ranges": {
      "range": {
        "field": "price",
        "keyed": true,
        "ranges": [
          { "key": "cheap",  "to": 100 },
          { "key": "mid",    "from": 100, "to": 500 },
          { "key": "premium","from": 500 }
        ]
      }
    }
  }
}'
```

**注意事项**：

- 区间边界：`from` 是包含的（`>=`），`to` 是不包含的（`<`）。若两端都指定则需保证 `from < to`。
- 区间可重叠，Elasticsearch 会将文档归入所有匹配的区间。
- 需确保字段支持 `doc_values`（数值类型默认开启）。

---

### date_range

**概念**：`range` 的日期特化版本，允许使用日期数学表达式（如 `now-1M/M`）及日期格式字符串。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `field` | string | — | 日期字段 |
| `ranges` | array | — | 区间定义，支持 `from`/`to` 使用日期数学表达式 |
| `format` | string | — | 日期格式（如 `yyyy-MM-dd`），影响返回 key 的展示形式 |
| `keyed` | bool | false | 同 `range` |
| `time_zone` | string | UTC | 时区（如 `+08:00`） |
| `missing` | string | — | 缺失值填充 |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/orders/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "order_periods": {
      "date_range": {
        "field": "created_at",
        "format": "yyyy-MM-dd",
        "time_zone": "+08:00",
        "keyed": true,
        "ranges": [
          { "key": "last_7d",  "from": "now-7d/d" },
          { "key": "last_30d", "from": "now-30d/d" },
          { "key": "older",    "to":   "now-30d/d" }
        ]
      }
    }
  }
}'
```

**注意事项**：

- 日期数学表达式参考：`now` 为当前时间，`/d` 向下舍入到天，`/M` 舍入到月；`-7d` 为 7 天前。
- `time_zone` 影响 `now` 的计算基准，务必设为业务时区。
- 日期字段存储为 UTC 毫秒时间戳，`format` 仅影响展示。

---

### histogram

**概念**：将数值字段按固定间隔（`interval`）切分为等宽桶，统计落入每个区间的文档数。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `field` | string | — | 数值字段 |
| `interval` | number | — | 桶宽度（必须为正数） |
| `min_doc_count` | int | 1 | 最小文档数阈值 |
| `extended_bounds` | object | — | 强制返回指定范围的桶（含空桶） |
| `hard_bounds` | object | — | 硬边界，超出范围的文档不计入 |
| `offset` | number | 0 | 桶起始偏移 |
| `keyed` | bool | false | 以 key 为键返回 |
| `missing` | number | — | 缺失值处理 |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/products/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "price_histogram": {
      "histogram": {
        "field": "price",
        "interval": 50,
        "min_doc_count": 1,
        "extended_bounds": { "min": 0, "max": 1000 },
        "offset": 0
      }
    }
  }
}'
```

**注意事项**：

- `interval` 是桶的宽度，不是桶的数量。如 `price ∈ [0, 1000]`，`interval=50` 产生约 20 个桶。
- `extended_bounds` 可强制填充空桶，保持时间序列或分布图的连续性。
- 浮点数 `interval` 会引入精度问题，建议使用 `offset` 对齐。

---

### date_histogram

**概念**：`histogram` 的日期版本，以时间间隔（`fixed_interval` 或 `calendar_interval`）为桶宽度，是最常用的时间序列聚合。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `field` | string | — | 日期字段 |
| `fixed_interval` | string | — | 固定间隔（如 `1h`、`30m`、`1d`），始终等长 |
| `calendar_interval` | string | — | 日历间隔（如 `1M`、`1q`、`1y`），长度随月份/年份变化 |
| `time_zone` | string | UTC | 时区 |
| `format` | string | — | 日期格式 |
| `min_doc_count` | int | 1 | 最小文档数 |
| `extended_bounds` | object | — | 强制返回边界 |
| `offset` | string | — | 偏移（如 `+6h`） |
| `keyed` | bool | false | 是否以 key 为键 |
| `missing` | string | — | 缺失值处理 |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/metrics/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "query": { "range": { "timestamp": { "gte": "now-7d", "lte": "now" } } },
  "aggs": {
    "events_per_hour": {
      "date_histogram": {
        "field": "timestamp",
        "fixed_interval": "1h",
        "time_zone": "+08:00",
        "format": "yyyy-MM-dd HH:mm",
        "min_doc_count": 1,
        "extended_bounds": { "min": "now-7d", "max": "now" }
      },
      "aggs": {
        "avg_latency": { "avg": { "field": "latency_ms" } }
      }
    }
  }
}'
```

**注意事项**：

- `fixed_interval` 与 `calendar_interval` 互斥，不可同时使用。
- `calendar_interval` 的 `1M` 表示日历月，天数不定（28-31 天），适用于月度报表。
- 大时间范围 + 细粒度间隔会产生巨量桶，建议配合 `min_doc_count` 或 `hard_bounds` 控制。

---

### filter

**概念**：将聚合范围限定在满足过滤条件的文档子集上，返回单个桶。等价于 `query` + 聚合，但可用于同级聚合中为不同子聚合指定不同过滤条件。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `filter` 子句 | object | — | 标准 Elasticsearch DSL 过滤条件（`term`、`range`、`bool` 等） |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/orders/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "paid_orders": {
      "filter": { "term": { "status.keyword": "paid" } },
      "aggs": {
        "avg_amount": { "avg": { "field": "total_amount" } }
      }
    }
  }
}'
```

**注意事项**：

- `filter` 聚合不影响查询的 `hits`，仅影响其子聚合的文档范围。
- 与 `post_filter` 的区别：`post_filter` 在聚合计算完成后作用于 `hits`，`filter` 聚合则在聚合阶段生效。
- 多个 `filter` 聚合可并列，实现"一次查询，多组条件"的聚合。

---

### filters

**概念**：`filter` 的多组版本，同时定义多个过滤条件，每个条件生成一个命名桶。适合"同一维度不同切面"的对比场景。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `filters` | object | — | 键值对：`{ "name": { filter_dsl } }` 或数组形式 |
| `other_bucket` | bool | false | 是否收集未匹配任何过滤器的文档 |
| `other_bucket_key` | string | `_other_` | 未匹配桶的 key 名称 |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/orders/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "status_groups": {
      "filters": {
        "other_bucket": true,
        "other_bucket_key": "other_status",
        "filters": {
          "paid":      { "term": { "status.keyword": "paid" } },
          "pending":   { "term": { "status.keyword": "pending" } },
          "high_value":{ "bool": { "must": [
            { "term": { "status.keyword": "paid" } },
            { "range": { "total_amount": { "gte": 1000 } } }
          ]}}
        }
      }
    }
  }
}'
```

**注意事项**：

- 命名过滤器的 key 不支持特殊字符。`other_bucket_key` 同理。
- 过滤器之间是独立执行的，文档可同时落入多个桶（与 `terms` 的互斥性不同）。
- 谨慎使用 `other_bucket`，在高基数场景下可能产生超大桶。

---

### global

**概念**：突破当前查询的过滤上下文，在全局数据集上执行聚合。常用于计算"总体占比"——查询限定了子集，但需同时获取全量基准值。

**核心参数**：无特有参数，`global` 聚合本身不接受参数。

**REST API 示例**：

```bash
curl -X POST "localhost:9200/orders/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "query": { "term": { "status.keyword": "paid" } },
  "aggs": {
    "paid_avg": { "avg": { "field": "total_amount" } },
    "all_orders": {
      "global": {},
      "aggs": {
        "overall_avg": { "avg": { "field": "total_amount" } }
      }
    }
  }
}'
```

**注意事项**：

- `global` 聚合无视 `query` 和上级 `filter` 聚合，始终在全部文档上计算。
- 性能开销等于"跑了一次全索引聚合"，大索引量下需谨慎。
- 常用于计算"转化率"：`filter` 聚合得分子，`global` 聚合得分母。

---

### missing

**概念**：将缺失字段值（`null`、字段不存在）的文档归入单一桶。用于评估数据完整性或填补空值。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `field` | string | — | 目标字段 |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/users/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "missing_email": {
      "missing": { "field": "email.keyword" }
    }
  }
}'
```

**注意事项**：

- 字段值为空字符串 `""` 不算缺失，仅 `null` 和字段不存在算缺失。
- 可在 `terms` 中通过 `missing` 参数设置缺失值占位，而 `missing` 聚合是独立桶。
- 常用于数据质量监控：统计缺失率。

---

### sampler / diversified_sampler

**概念**：对文档进行采样后聚合，减少计算量。`sampler` 随机采样；`diversified_sampler` 按指定字段（如 `user_id`）去重采样，确保样本多样性。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `shard_size` | int | — | 每个 shard 采样的文档数（上限） |
| `field` | string | — | (`diversified_sampler` 必需) 多样性控制字段 |
| `max_docs_per_value` | int | 1 | (`diversified_sampler`) 每个唯一值最多保留的文档数 |
| `execution_hint` | string | `global_ordinals` | 执行策略 |

**REST API 示例**：

```bash
# sampler
curl -X POST "localhost:9200/logs/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "sample": {
      "sampler": { "shard_size": 200 },
      "aggs": {
        "keywords": { "significant_terms": { "field": "message" } }
      }
    }
  }
}'

# diversified_sampler
curl -X POST "localhost:9200/events/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "diverse_sample": {
      "diversified_sampler": {
        "shard_size": 1000,
        "field": "user_id",
        "max_docs_per_value": 5
      },
      "aggs": {
        "top_actions": { "terms": { "field": "action.keyword" } }
      }
    }
  }
}'
```

**注意事项**：

- 采样聚合的结果是估计值，不可用于精确统计。
- `diversified_sampler` 依赖 `global_ordinals` 或 `fielddata`，`field` 应为 keyword 类型。
- `shard_size` 是单 shard 限制，实际采样量 = `shard_size * shard_count`。

### composite

**概念**：基于多个 source 组合分桶，并支持游标分页（无限滚动），是 `terms` 聚合的"精确分页 + 多字段组合"替代方案。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `size` | int | 10 | 每页返回的桶数 |
| `sources` | array | — | 组合分桶的 source 列表，每个 source 定义字段和排序 |
| `after` | object | — | 分页游标，从上一次结果的 `after_key` 传入 |

**Source 类型**：`terms`、`histogram`、`date_histogram`、`geotile_grid`。

**REST API 示例**：

```bash
curl -X POST "localhost:9200/orders/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "composite_buckets": {
      "composite": {
        "size": 100,
        "sources": [
          { "status": { "terms": { "field": "status.keyword" } } },
          { "month": { "date_histogram": { "field": "created_at", "calendar_interval": "1M" } } }
        ]
      },
      "aggs": {
        "total_revenue": { "sum": { "field": "total_amount" } }
      }
    }
  }
}'
```

**注意事项**：

- `composite` 聚合是**唯一**支持精确分页的聚合类型，`after_key` 是无状态的游标。
- 性能比 `terms(size=10000)` 更稳定，但单页延迟略高。
- 不支持 `order` 参数，排序由 `sources` 列表中的顺序和每个 source 的 `order` 决定。
- `after_key` 必须在下一页原样回传，不可修改。

## Metric 聚合

### avg

**概念**：计算指定字段的算术平均值。`avg = sum(values) / count(values)`。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `field` | string | — | 数值字段 |
| `missing` | number | — | 缺失值填充，填充值参与计算 |
| `script` | object | — | 自定义脚本计算（替代 `field`）|

**REST API 示例**：

```bash
curl -X POST "localhost:9200/orders/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "avg_amount": {
      "avg": { "field": "total_amount", "missing": 0 }
    }
  }
}'
```

**注意事项**：

- `missing` 参数填充的文档仅影响当前聚合，不修改 `_source`。
- 若所有文档的字段均缺失且未设 `missing`，返回 `value: null`。
- 字段类型必须为数值型（`integer`、`long`、`float`、`double`、`scaled_float` 等）。

---

### sum

**概念**：计算指定字段的数值总和。

**核心参数**：同 `avg`（`field`、`missing`、`script`）。

**REST API 示例**：

```bash
curl -X POST "localhost:9200/orders/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "total_revenue": {
      "sum": { "field": "total_amount" }
    }
  }
}'
```

**注意事项**：

- 大数值求和可能溢出，ES 内部使用 `double` 存储，超大值有精度损失。
- 与 `value_count` 组合可计算均值：`sum / value_count`。

---

### max / min

**概念**：分别返回字段的最大值和最小值。

**核心参数**：同 `avg`。

**REST API 示例**：

```bash
curl -X POST "localhost:9200/products/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "max_price": { "max": { "field": "price" } },
    "min_price": { "min": { "field": "price" } }
  }
}'
```

**注意事项**：

- 对 `date` 字段使用 `max`/`min` 返回毫秒时间戳，可配合 `format` 参数格式化。
- 字符串字段按字典序取最大/最小，但通常不推荐。

---

### stats / extended_stats

**概念**：`stats` 一次性返回 `count`、`min`、`max`、`avg`、`sum`。`extended_stats` 额外返回 `std_deviation`、`variance`、`sum_of_squares` 及标准差边界。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `field` | string | — | 数值字段 |
| `sigma` | number | 2 | (`extended_stats`) 标准差边界倍数 |
| `missing` | number | — | 缺失值填充 |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/products/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "price_stats": {
      "extended_stats": { "field": "price", "sigma": 3 }
    }
  }
}'
```

**注意事项**：

- `extended_stats` 是 `stats` 的超集，无特殊需求可直接用 `extended_stats`。
- `sigma` 边界可用于异常检测：`avg - sigma * std` 到 `avg + sigma * std` 为正常范围。
- 标准差计算基于总体标准差（`population`），非样本标准差。

---

### cardinality

**概念**：对字段值进行近似去重计数（类似 SQL 的 `COUNT(DISTINCT field)`）。基于 HyperLogLog++ 算法，可配置精度。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `field` | string | — | 目标字段 |
| `precision_threshold` | int | 3000 | 精度阈值，上限 40000；值越大越精确但内存开销越大 |
| `missing` | string | — | 缺失值绑定 |
| `execution_hint` | string | `direct` | 执行策略：`direct`（直接）、`global_ordinals`（全局序数，适用于 keyword 字段） |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/orders/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "unique_users": {
      "cardinality": {
        "field": "user_id",
        "precision_threshold": 10000
      }
    }
  }
}'
```

**注意事项**：

- 结果始终是近似值，误差在 `precision_threshold` 以内通常 < 1%。
- `precision_threshold` 为 100 时内存约 1KB，10000 时约 100KB。需权衡精度与内存。
- 跨 shard 的 `cardinality` 会分别计算后合并，误差叠加。
- 需要精确去重计数时，考虑使用 `scripted_metric` 或 `collapse` 替代。

---

### value_count

**概念**：统计字段非空值的文档数量（类似 SQL 的 `COUNT(field)`）。注意与 `_count` 的区别：`_count` 统计桶内文档总数，`value_count` 仅统计字段有值的文档。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `field` | string | — | 目标字段 |
| `script` | object | — | 脚本替代字段 |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/users/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "has_email_count": {
      "value_count": { "field": "email.keyword" }
    }
  }
}'
```

**注意事项**：

- `value_count` 不统计 `null` 值，但会统计空字符串 `""`。
- 与 `missing` 聚合配合，可计算数据完整率：`value_count / (value_count + missing_count)`。

---

### percentiles / percentile_ranks

**概念**：`percentiles` 计算字段值的百分位分布（如 P50、P95、P99）。`percentile_ranks` 反向计算——给定值在分布中的百分位排名。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `field` | string | — | 数值字段 |
| `percents` | double[] | `[1,5,25,50,75,95,99]` | 目标百分位 |
| `keyed` | bool | true | 是否以百分位值为键 |
| `tdigest` | object | `compression=100` | TDigest 算法参数 |
| `hdr` | object | — | HDR Histogram 算法参数（替代 TDigest） |
| `missing` | number | — | 缺失值 |

**REST API 示例**：

```bash
# percentiles
curl -X POST "localhost:9200/metrics/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "latency_percentiles": {
      "percentiles": {
        "field": "latency_ms",
        "percents": [ 50, 90, 95, 99, 99.9 ],
        "keyed": false
      }
    }
  }
}'

# percentile_ranks
curl -X POST "localhost:9200/metrics/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "latency_rank": {
      "percentile_ranks": {
        "field": "latency_ms",
        "values": [ 100, 500, 1000 ],
        "keyed": false
      }
    }
  }
}'
```

**注意事项**：

- 默认使用 **TDigest** 算法，`compression` 越大精度越高（默认 100，最大 1000）。
- 高精度需求（如金融领域）可改用 **HDR Histogram**，需指定 `number_of_significant_value_digits`。
- 百分位聚合是近似的，近似程度取决于数据分布和算法参数。
- 使用 `percentile_ranks` 时，`values` 必须是严格递增的。

---

### top_hits

**概念**：返回每个桶内的 Top N 条原始文档，支持排序和字段筛选。常与 `terms` 组合，获取每个分组下的代表性文档。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `size` | int | 3 | 每个桶返回的文档数 |
| `sort` | array | `_score desc` | 排序规则 |
| `_source` | object | 全部字段 | 字段过滤（`includes`/`excludes`） |
| `from` | int | 0 | 偏移量 |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/orders/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "by_user": {
      "terms": { "field": "user_id", "size": 10 },
      "aggs": {
        "latest_order": {
          "top_hits": {
            "size": 1,
            "sort": [ { "created_at": { "order": "desc" } } ],
            "_source": { "includes": [ "order_id", "total_amount", "created_at" ] }
          }
        }
      }
    }
  }
}'
```

**注意事项**：

- `top_hits` 会读取 `_source`，开销远大于普通 Metric 聚合，大桶 + 大 `size` 时需谨慎。
- 子聚合的 `top_hits` 不会触发 `fetch` 阶段，而是利用 `doc_values` 或 `_source` 直接返回。
- 与 `collapse` 不同：`top_hits` 可作为子聚合嵌入任意 Bucket，灵活性更高。

---

### top_metrics

**概念**：`top_hits` 的轻量版，仅返回排序后的 Top 1 条文档的指定字段值（基于 `doc_values`），不加载 `_source`，性能显著优于 `top_hits`。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `metrics` | array | — | 要返回的字段列表（`{ "field": "..." }`） |
| `sort` | array | — | 排序规则（必需，决定"Top"的定义） |
| `size` | int | 1 | 最大返回数（1-10） |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/orders/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "by_user": {
      "terms": { "field": "user_id", "size": 10 },
      "aggs": {
        "latest_order_metrics": {
          "top_metrics": {
            "metrics": [
              { "field": "order_id" },
              { "field": "total_amount" }
            ],
            "sort": { "created_at": "desc" },
            "size": 1
          }
        }
      }
    }
  }
}'
```

**注意事项**：

- `metrics` 中的字段必须支持 `doc_values`（keyword、数值、日期等默认开启）。
- 不支持返回 `_source` 或 `text` 字段。
- 仅支持 `size` 1-10（单个桶内），远小于 `top_hits` 的灵活性。
- `sort` 是必需参数，且排序字段也需支持 `doc_values`。

---

### geo_bounds / geo_centroid

**概念**：`geo_bounds` 返回地理点集合的边界矩形（左上角 + 右下角）。`geo_centroid` 返回地理中心点（算术平均）。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `field` | string | — | `geo_point` 类型字段 |
| `wrap_longitude` | bool | true | (`geo_bounds`) 是否处理跨越 180 度经线的情况 |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/stores/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "area": {
      "geo_bounds": { "field": "location" }
    },
    "center": {
      "geo_centroid": { "field": "location" }
    }
  }
}'
```

**注意事项**：

- 仅适用于 `geo_point` 字段，不对 `geo_shape` 生效。
- `geo_centroid` 是算术平均，不一定落在实际数据点中。
- 跨国场景需开启 `wrap_longitude` 避免经度跨越问题。

---

## Pipeline 聚合

### derivative

**概念**：计算父级聚合桶之间指标值的差值（一阶导数）。常用于时间序列的环比变化分析。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `buckets_path` | string | — | 指向父级聚合的路径 |
| `unit` | string | — | 时间单位（如 `1h`、`1d`），用于归一化 |
| `gap_policy` | string | `skip` | 空桶策略：`skip`（跳过）、`insert_zeros`（插入 0）、`keep_values`（保留） |
| `format` | string | — | 数值格式化 |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/sales/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "sales_per_month": {
      "date_histogram": {
        "field": "date",
        "calendar_interval": "1M"
      },
      "aggs": {
        "revenue": { "sum": { "field": "amount" } },
        "revenue_change": {
          "derivative": {
            "buckets_path": "revenue"
          }
        }
      }
    }
  }
}'
```

**注意事项**：

- 第一个桶的 `derivative` 值为 `null`（无前值可减）。
- `buckets_path` 使用点号路径，如 `"sales_per_month>revenue"`（跨层级引用时需加父级前缀）。
- 时间序列间隔不均匀时，建议使用 `unit` 归一化。

---

### moving_avg / moving_fn

**概念**：滑动窗口聚合。`moving_avg` 计算移动平均（支持 `linear`、`simple`、`ewma`、`holt`、`holt_winters` 模型）。`moving_fn` 支持自定义窗口函数（`min`、`max`、`sum`、`stdDev`、`linearWeightedAvg` 等）。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `buckets_path` | string | — | 父级聚合路径 |
| `window` | int | 5 | 窗口大小 |
| `model` | string | `simple` | (`moving_avg`) 平滑模型 |
| `minimize` | bool | — | (`moving_avg`) 是否最小化预测误差 |
| `predict` | int | — | (`moving_avg`) 预测未来桶数 |
| `script` | string | — | (`moving_fn`) 自定义脚本 |
| `gap_policy` | string | `skip` | 空桶策略 |

**REST API 示例**：

```bash
# moving_avg
curl -X POST "localhost:9200/sales/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "sales_per_day": {
      "date_histogram": { "field": "date", "fixed_interval": "1d" },
      "aggs": {
        "revenue": { "sum": { "field": "amount" } },
        "smoothed_revenue": {
          "moving_avg": {
            "buckets_path": "revenue",
            "window": 7,
            "model": "linear"
          }
        }
      }
    }
  }
}'

# moving_fn
curl -X POST "localhost:9200/sales/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "sales_per_day": {
      "date_histogram": { "field": "date", "fixed_interval": "1d" },
      "aggs": {
        "revenue": { "sum": { "field": "amount" } },
        "max_7d": {
          "moving_fn": {
            "buckets_path": "revenue",
            "window": 7,
            "script": "MovingFunctions.max(values)"
          }
        }
      }
    }
  }
}'
```

**注意事项**：

- `moving_avg` 的 `linear`、`simple` 等模型是 ES 内置的，无需额外配置。
- `moving_fn` 中的 `MovingFunctions` 内置函数：`max()`、`min()`、`sum()`、`unweightedAvg()`、`linearWeightedAvg()`、`ewma()`、`holt()`、`holtWinters()`。
- 窗口小于数据点数时，前 `window - 1` 个桶的聚合结果为 `null`。

---

### cumulative_sum

**概念**：计算父级聚合值的累计和（逐桶累加）。常用于绘制累计趋势图。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `buckets_path` | string | — | 父级聚合路径 |
| `format` | string | — | 数值格式化 |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/sales/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "sales_per_month": {
      "date_histogram": { "field": "date", "calendar_interval": "1M" },
      "aggs": {
        "revenue": { "sum": { "field": "amount" } },
        "cumulative_revenue": {
          "cumulative_sum": { "buckets_path": "revenue" }
        }
      }
    }
  }
}'
```

**注意事项**：

- 累计计算按桶顺序依次进行，依赖桶的排序稳定性。
- 空桶（`gap_policy=skip`）不参与累计，但后续桶会继续累加。
- 与 `derivative` 互为逆运算：`cumulative_sum(derivative(x)) ≈ x`。

---

### bucket_script

**概念**：在多个父级聚合结果间执行自定义 Painless 脚本运算，生成新的聚合指标。是 Pipeline 聚合中最灵活的计算工具。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `buckets_path` | object | — | 多路径映射，key 为变量名，value 为聚合路径 |
| `script` | string | — | Painless 脚本，通过 `params` 访问变量 |
| `gap_policy` | string | `skip` | 空桶策略 |
| `format` | string | — | 数值格式化 |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/sales/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "sales_per_month": {
      "date_histogram": { "field": "date", "calendar_interval": "1M" },
      "aggs": {
        "revenue": { "sum": { "field": "amount" } },
        "order_count": { "value_count": { "field": "order_id" } },
        "avg_order_value": {
          "bucket_script": {
            "buckets_path": {
              "totalRev": "revenue",
              "count": "order_count"
            },
            "script": "params.totalRev / params.count",
            "format": "#,##0.00"
          }
        }
      }
    }
  }
}'
```

**注意事项**：

- 脚本中除零不会抛异常，但结果为 `Infinity` 或 `NaN`，建议加保护：`params.count > 0 ? params.totalRev / params.count : 0`。
- `buckets_path` 的 key 成为脚本中 `params` 对象的属性名。
- 可引用任意深度的聚合，路径语法为 `agg_name>sub_agg_name`。

---

### bucket_selector

**概念**：根据脚本条件过滤桶，仅保留满足条件的桶。等价于 SQL 的 `HAVING` 子句。

**核心参数**：同 `bucket_script`，但脚本需返回 `boolean` 值。

**REST API 示例**：

```bash
curl -X POST "localhost:9200/sales/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "sales_per_month": {
      "date_histogram": { "field": "date", "calendar_interval": "1M" },
      "aggs": {
        "revenue": { "sum": { "field": "amount" } },
        "high_revenue_months": {
          "bucket_selector": {
            "buckets_path": { "monthlyRev": "revenue" },
            "script": "params.monthlyRev > 100000"
          }
        }
      }
    }
  }
}'
```

**注意事项**：

- `bucket_selector` 不改变桶内的任何聚合结果，仅决定桶是否出现在最终输出中。
- 过滤后的桶仍计入 `date_histogram` 的 `min_doc_count` 等 min 阈值检查。
- 性能优于先计算再在应用层过滤，因为被过滤的桶不参与后续 Pipeline 计算。

---

### bucket_sort

**概念**：对父级聚合的桶进行排序和分页，不受 `terms` 的 `order` 参数限制。支持多字段排序和截断。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `sort` | array | — | 排序规则列表，支持 `{ "metric_path": { "order": "asc/desc" } }` |
| `from` | int | 0 | 偏移量（分页起始） |
| `size` | int | 全部 | 返回的桶数量上限 |
| `gap_policy` | string | `skip` | 空桶策略 |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/sales/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "sales_per_month": {
      "date_histogram": { "field": "date", "calendar_interval": "1M" },
      "aggs": {
        "revenue": { "sum": { "field": "amount" } },
        "order_count": { "value_count": { "field": "order_id" } },
        "top_by_revenue": {
          "bucket_sort": {
            "sort": [
              { "revenue": { "order": "desc" } },
              { "order_count": { "order": "desc" } }
            ],
            "from": 0,
            "size": 5
          }
        }
      }
    }
  }
}'
```

**注意事项**：

- `bucket_sort` 是截断型操作，被截断的桶不会出现在输出中，也不参与后续 Pipeline 聚合。
- 排序引用同级的子聚合名称，而非 `buckets_path` 路径。
- `from` + `size` 可实现基于聚合的分页（但非无状态，需保持查询条件一致）。

---

### serial_diff

**概念**：计算当前桶与前面第 `lag` 个桶的差值（序列差分）。与 `derivative` 类似，但可指定滞后步长。

**核心参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `buckets_path` | string | — | 父级聚合路径 |
| `lag` | int | 1 | 滞后步长（1 表示与前一个桶的差值，7 表示与 7 个桶前的差值） |
| `gap_policy` | string | `skip` | 空桶策略 |
| `format` | string | — | 数值格式化 |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/sales/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "sales_per_day": {
      "date_histogram": { "field": "date", "fixed_interval": "1d" },
      "aggs": {
        "revenue": { "sum": { "field": "amount" } },
        "wow_change": {
          "serial_diff": {
            "buckets_path": "revenue",
            "lag": 7
          }
        }
      }
    }
  }
}'
```

**注意事项**：

- `lag=1` 时 `serial_diff` 与 `derivative` 等价。
- 前 `lag` 个桶的值为 `null`。
- 常用于周同比（`lag=7`）、月同比（`lag=30`）等场景。

## 聚合优化

### shard_size 调优

**概念**：`shard_size` 是 `terms` 聚合（及 `significant_terms`、`sampler`）中每个 shard 返回的桶数量上限。默认值为 `size * 1.5 + 10`。

**调优策略**：

| 场景 | 推荐 shard_size | 理由 |
|------|----------------|------|
| 小基数，高精度 | `size * 10` | 确保每个 shard 返回足够多的候选，减少坐标误差 |
| 中等基数，平衡 | `size * 2 ~ size * 4` | 精度与性能折中 |
| 高基数，仅需 Top N | `size * 1.5`（默认） | 减少 shard 级内存开销 |
| 精确计数需求 | 改用 `composite` 聚合 | `terms` 聚合本质上是近似的 |

**注意事项**：

- `shard_size` 增大意味着更多数据在 coordinator 节点合并，内存和网络开销线性增长。
- 可通过 `show_term_doc_count_error` 参数观测误差，决定是否需要调大 `shard_size`。
- 对于 `size=10`（默认），`shard_size` 默认仅 25，这在数据倾斜时可能产生较大误差。

---

### execution_hint

**概念**：为 `terms` 聚合提供执行策略提示，控制 Elasticsearch 使用哪种内部数据结构进行计算。

**可选值**：

| 值 | 机制 | 适用场景 |
|-----|------|----------|
| `global_ordinals` | 使用全局序数（默认） | keyword 字段，中等基数 |
| `map` | 直接用字段值做 HashMap 键 | 低基数，或字段值本身就是序数性较好的 |
| `global_ordinals_hash` | 全局序数 + HashMap | 高基数 keyword 字段 |
| `global_ordinals_low_cardinality` | 全局序数 + 优化低基数路径 | 极低基数（如枚举值） |

**REST API 示例**：

```bash
curl -X POST "localhost:9200/logs/_search?pretty" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "by_status": {
      "terms": {
        "field": "status.keyword",
        "execution_hint": "map"
      }
    }
  }
}'
```

**注意事项**：

- 多数情况下无需手动设置，ES 会自动选择。仅在确认当前策略不优时调整。
- `map` 对低基数（< 100 个唯一值）字段最快，但高基数内存占用飙升。
- 8.x 中 `global_ordinals` 为所有 keyword 字段默认启用，无需额外配置。

### 预聚合（Rollup / Downsampling）

**Rollup（已废弃，7.x 阶段）**：通过 Rollup Job 对历史数据进行预聚合，写入独立索引，查询时用 Rollup Search API 读取。

**Downsampling（8.x 推荐）**：8.x 引入的下采样机制，是 Rollup 的继任者。通过 ILM（索引生命周期管理）在索引进入 `warm`/`cold` 阶段时自动对时间序列数据进行降采样。

**Downsampling 核心概念**：

| 概念 | 说明 |
|------|------|
| 触发时机 | ILM 的 `downsample` action |
| 支持聚合 | `min`、`max`、`sum`、`avg`、`value_count`、`last_value` |
| 时间间隔 | `fixed_interval`（如 `1h`、`1d`），将原始数据压缩到固定时间桶 |
| 存储节省 | 通常 50%-90% 的存储缩减 |

**REST API 示例（手动 Downsampling）**：

```bash
curl -X POST "localhost:9200/metrics-2024/_downsample/metrics-2024-1h" -H 'Content-Type: application/json' -d '{
  "fixed_interval": "1h"
}'
```

**注意事项**：

- Downsampling 后，原始粒度数据不可恢复。查询时需使用降采样后的聚合粒度。
- 仅适用于 `tsdb`（时间序列数据流）或 `metrics` 类型索引。
- 降采样后不支持 `update`、`delete` 操作，索引变为只读。
- 8.x 中 Downsampling 是生产级特性，但需在索引模板中预先配置 ILM 策略。

---

### eager_global_ordinals

**概念**：全局序数（Global Ordinals）是 keyword 字段的序数映射表，将每个唯一字符串值映射为一个整数，加速 `terms` 聚合。默认在首次聚合时懒加载（构建耗时长），`eager_global_ordinals` 可强制在索引刷新时提前构建。

**映射配置示例**：

```bash
curl -X PUT "localhost:9200/orders" -H 'Content-Type: application/json' -d '{
  "mappings": {
    "properties": {
      "status": {
        "type": "keyword",
        "eager_global_ordinals": true
      }
    }
  }
}'
```

**注意事项**：

- 仅在字段被频繁用于 `terms` 聚合且数据量不大时启用，否则会增加索引刷新开销。
- 高基数字段（> 100 万唯一值）不建议启用，全局序数构建本身就很昂贵。
- 可通过 `GET _nodes/stats/indices/fielddata` 监控全局序数内存占用。
- 8.x 中 `eager_global_ordinals` 默认 `false`，需显式开启。

### 聚合缓存与内存控制

**聚合缓存机制**：

| 缓存类型 | 作用范围 | 说明 |
|----------|----------|------|
| 请求级缓存 | 单次请求 | 同级聚合共享中间结果，无需额外配置 |
| Shard 请求缓存 | Shard 级 | 对 `size=0` 的查询有效，缓存聚合结果（默认最多占堆内存 1%） |
| Field Data 缓存 | 节点级 | 用于 `text` 字段的 `fielddata`，默认无限制（需配置断路器） |

**内存控制参数**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `indices.requests.cache.size` | 1% | Shard 请求缓存占堆内存比例 |
| `indices.fielddata.cache.size` | 无限制 | Field Data 缓存上限（强烈建议限制） |
| `indices.breaker.fielddata.limit` | 40% | Field Data 断路器上限 |
| `indices.breaker.request.limit` | 60% | 请求断路器上限 |
| `search.max_buckets` | 65536 | 单次查询最大桶数（动态设置） |

**最佳实践**：

- 对所有聚合查询设置 `size: 0`，以利用 Shard 请求缓存。
- 对高基数字段避免使用 `terms`，改用 `composite` 或 `cardinality`。
- 设置 `search.max_buckets` 防止爆炸式桶数导致的 OOM：

```bash
curl -X PUT "localhost:9200/_cluster/settings" -H 'Content-Type: application/json' -d '{
  "persistent": { "search.max_buckets": 100000 }
}'
```

- 使用 `timeout` 参数防止聚合查询长时间占用资源：

```bash
curl -X POST "localhost:9200/logs/_search?timeout=30s" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": { "by_date": { "date_histogram": { "field": "timestamp", "fixed_interval": "1h" } } }
}'
```

- 监控聚合性能：`GET _nodes/stats/indices/search` 关注 `aggregations` 相关指标。
