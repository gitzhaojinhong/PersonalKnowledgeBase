## Mapping

### Dynamic Mapping

**概念定义**

Dynamic Mapping 是 Elasticsearch 在索引文档时，对未预先定义 Mapping 的字段自动推断数据类型并生成映射的机制。无需手动为每个字段声明类型，ES 根据 JSON 值的形态自动推导。

**类型推断规则**

| JSON 值类型 | 推断的 ES 字段类型 |
|---|---|
| `null` | 不添加字段 |
| `true` / `false` | `boolean` |
| 整数（`123`） | `long` |
| 浮点数（`123.45`） | `float` |
| 字符串（`"abc"`） | `text` + 子字段 `keyword` |
| 日期格式字符串（`"2024-01-01"`） | `date` |
| 数组（`[1,2,3]`） | 取第一个非空元素类型 |
| 对象（`{"a":1}`） | `object`（展平为 `a` 字段） |

**核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `dynamic` | `true` / `false` / `runtime` / `strict` | `true` | 控制动态字段行为 |
| `dynamic_date_formats` | `["yyyy-MM-dd", ...]` | `["strict_date_optional_time", "yyyy/MM/dd HH:mm:ss Z"]` | 日期检测格式列表 |
| `numeric_detection` | `true` / `false` | `false` | 是否将字符串数字转为数值类型 |
| `date_detection` | `true` / `false` | `true` | 是否启用日期检测 |

**REST API 示例**

```bash
# 1. 创建索引时配置 Dynamic Mapping 策略
curl -X PUT "localhost:9200/my_index" -H "Content-Type: application/json" -d '{
  "mappings": {
    "dynamic": "strict",
    "dynamic_date_formats": ["yyyy-MM-dd", "yyyy/MM/dd"],
    "numeric_detection": true,
    "properties": {
      "title": { "type": "text" }
    }
  }
}'

# 2. 查看 Dynamic Mapping 模板
curl -X GET "localhost:9200/_mapping?pretty"

# 3. 测试 Dynamic Mapping（不创建索引，仅预览推断结果）
curl -X POST "localhost:9200/_mapping/simulate?pretty" -H "Content-Type: application/json" -d '{
  "index": "my_index",
  "doc": {
    "count": 100,
    "price": 99.99,
    "name": "hello",
    "created": "2024-01-15",
    "flag": true
  }
}'
```

**注意事项**

- `dynamic: strict` 时，写入未声明字段会直接报错（HTTP 400），适合对 Schema 强约束的场景。
- `dynamic: runtime` 是 7.11+ 特性，动态字段以 Runtime Field 形式存在，不占磁盘但查询性能低于索引字段。
- `numeric_detection` 开启后，字符串 `"123"` 会被推断为 `long` 而非 `text`，需确保业务语义正确。
- 类型推断仅基于索引中第一条文档的字段值，后续文档若同名字段类型不同会触发 `mapper_parsing_exception`。

### Explicit Mapping

**概念定义**

Explicit Mapping 是在创建索引时或通过 `_mapping` API 显式声明每个字段的数据类型、分析器及参数。与 Dynamic Mapping 互补，适用于 Schema 已知且需要精确控制索引行为的场景。

**核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `type` | `text` / `keyword` / `long` / `date` 等 | 无（必填） | 字段数据类型 |
| `analyzer` | 任意已注册分析器名 | `standard` | 索引时分析器 |
| `search_analyzer` | 任意已注册分析器名 | 同 analyzer | 搜索时分析器 |
| `fields` | 子字段定义对象 | 无 | 同一字段的多映射（multi-fields） |

**REST API 示例**

```bash
# 1. 创建索引时显式声明 Mapping
curl -X PUT "localhost:9200/products" -H "Content-Type: application/json" -d '{
  "mappings": {
    "properties": {
      "sku": {
        "type": "keyword"
      },
      "name": {
        "type": "text",
        "analyzer": "ik_max_word",
        "search_analyzer": "ik_smart",
        "fields": {
          "raw": { "type": "keyword" },
          "pinyin": { "type": "text", "analyzer": "pinyin_analyzer" }
        }
      },
      "price": {
        "type": "double"
      },
      "created_at": {
        "type": "date",
        "format": "yyyy-MM-dd HH:mm:ss||yyyy-MM-dd||epoch_millis"
      }
    }
  }
}'

# 2. 为已有索引追加字段
curl -X PUT "localhost:9200/products/_mapping" -H "Content-Type: application/json" -d '{
  "properties": {
    "description": {
      "type": "text",
      "analyzer": "ik_max_word"
    }
  }
}'

# 3. 查看索引 Mapping
curl -X GET "localhost:9200/products/_mapping?pretty"
```

**注意事项**

- 已存在的字段类型不可修改（只能追加新字段），如需变更类型需 Reindex。
- Multi-fields 不会增加额外的磁盘开销（共享同一份倒排索引数据源）。
- `analyzer` 与 `search_analyzer` 分离可实现索引粒度细、搜索粒度粗的策略（如索引用 `ik_max_word`，搜索用 `ik_smart`）。

### Runtime Field

**概念定义**

Runtime Field 是在查询时动态计算字段值的机制，字段值不在索引时写入磁盘，而是在搜索时通过 Painless 脚本或预定义的 Runtime 类型实时计算。ES 8.x 支持 `keyword`、`long`、`double`、`date`、`boolean`、`ip`、`geo_point` 七种 Runtime 类型。

**核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `type` | `keyword` / `long` / `double` / `date` / `boolean` / `ip` / `geo_point` | 无（必填） | Runtime 字段类型 |
| `script` | Painless 脚本源码 | 无 | 计算逻辑（与 `field` 二选一） |
| `field` | 源字段名 | 无 | 从 `_source` 直取（无需脚本） |
| `format` | 日期格式 | 无 | 仅 `date` 类型需要 |

**REST API 示例**

```bash
# 1. 在 Mapping 中定义 Runtime Field
curl -X PUT "localhost:9200/orders" -H "Content-Type: application/json" -d '{
  "mappings": {
    "runtime": {
      "total_amount": {
        "type": "double",
        "script": {
          "source": "emit(doc['unit_price'].value * doc['quantity'].value)"
        }
      },
      "day_of_week": {
        "type": "keyword",
        "script": {
          "source": "emit(doc['created_at'].value.dayOfWeekEnum.toString())"
        }
      }
    },
    "properties": {
      "unit_price": { "type": "double" },
      "quantity": { "type": "integer" },
      "created_at": { "type": "date" }
    }
  }
}'

# 2. 在搜索请求中动态定义 Runtime Field
curl -X POST "localhost:9200/orders/_search" -H "Content-Type: application/json" -d '{
  "runtime_mappings": {
    "discount_price": {
      "type": "double",
      "script": {
        "source": "emit(doc['unit_price'].value * 0.9)"
      }
    }
  },
  "query": {
    "range": {
      "discount_price": { "gte": 100 }
    }
  }
}'

# 3. 使用 field 方式从 _source 直接取值
curl -X POST "localhost:9200/orders/_search" -H "Content-Type: application/json" -d '{
  "runtime_mappings": {
    "status_code": {
      "type": "keyword",
      "field": "status.keyword"
    }
  }
}'
```

**注意事项**

- `doc['field']` 访问的是索引字段（Doc Values），速度快但不支持 text 类型；`params._source.field` 访问原始 JSON，支持所有字段但速度慢。
- Runtime Field 不支持 `analyzer` 参数，`keyword` 类型的 Runtime Field 不会分词。
- 大量 Runtime Field 聚合会显著增加查询延迟，建议对高频聚合场景使用索引字段。
- `field` 方式（无脚本）性能与普通字段相当，优先使用。

### 常用 Mapping 参数

**概念定义**

Mapping 参数是附加在字段定义上的元数据选项，控制字段的索引方式、存储策略、查询行为等。每个字段类型支持的参数子集不同。

**核心参数表格**

| 参数 | 适用类型 | 默认值 | 说明 |
|---|---|---|---|
| `index` | 除 binary 外所有类型 | `true` | 是否构建倒排索引，`false` 时字段不可搜索 |
| `doc_values` | keyword / 数值 / date / boolean / geo_point / ip | `true` | 是否构建列式存储（用于聚合/排序/脚本访问） |
| `store` | 所有类型 | `false` | 是否独立存储字段值（与 `_source` 分离） |
| `norms` | text / keyword | `true` | 是否存储归一化因子（用于评分，text 类型默认开启） |
| `coerce` | 数值 / date / boolean / ip / geo_point | `true` | 是否自动类型转换（如 `"5"` → `5`） |
| `ignore_above` | keyword / text 子字段 | `2147483647` | 超过此长度的字符串不索引（不可搜索）但可存储 |
| `enabled` | object / nested | `true` | 是否解析该对象字段，`false` 时整个对象不可搜索 |
| `eager_global_ordinals` | keyword | `false` | 是否在 refresh 时提前构建全局序数（加速聚合，增加内存） |
| `null_value` | 数值 / keyword / date / boolean / ip / geo_point | `null` | 索引时将 null 替换为指定值 |
| `copy_to` | text / keyword | 无 | 将字段值拷贝到目标字段（支持多源合并） |

**REST API 示例**

```bash
# 1. 综合参数示例
curl -X PUT "localhost:9200/users" -H "Content-Type: application/json" -d '{
  "mappings": {
    "properties": {
      "email": {
        "type": "keyword",
        "ignore_above": 256
      },
      "bio": {
        "type": "text",
        "index": true,
        "norms": false,
        "doc_values": false,
        "copy_to": "all_text"
      },
      "age": {
        "type": "integer",
        "coerce": true,
        "null_value": 0
      },
      "score": {
        "type": "double",
        "index": false,
        "doc_values": true,
        "store": true
      },
      "metadata": {
        "type": "object",
        "enabled": false
      },
      "all_text": {
        "type": "text"
      }
    }
  }
}'

# 2. 查看字段参数
curl -X GET "localhost:9200/users/_mapping/field/email?pretty"
```

**注意事项**

- `doc_values: false` 后字段无法聚合/排序，但可节省磁盘空间。text 类型默认 `doc_values: false`。
- `norms: false` 禁用评分归一化，适合仅需过滤（不需相关性排序）的 text 字段，可显著节省磁盘。
- `store: true` 会将字段独立存储，适合需要高亮但 `_source` 已关闭的场景，一般不推荐开启。
- `ignore_above` 仅阻止索引，`_source` 中仍保留完整值，可用于展示。
- `coerce` 默认开启，写入 `"5"` 到 integer 字段不会报错，关闭后严格校验类型。

## 字段数据类型

### text

**概念定义**

text 类型用于全文搜索，写入时会经过分析器（Analyzer）分词成词项（Term），构建倒排索引。不支持聚合和排序（除非使用 `fielddata: true`，不推荐）。

**核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `analyzer` | 分析器名称 | `standard` | 索引时分析器 |
| `search_analyzer` | 分析器名称 | 同 analyzer | 搜索时分析器 |
| `index` | `true` / `false` | `true` | 是否可搜索 |
| `norms` | `true` / `false` | `true` | 是否存储评分因子 |
| `fielddata` | `true` / `false` | `false` | 是否启用 fielddata（慎用） |
| `index_options` | `docs` / `freqs` / `positions` / `offsets` | `positions` | 索引粒度 |
| `term_vector` | `no` / `yes` / `with_positions` / `with_offsets` / `with_positions_offsets` | `no` | 词向量存储策略 |
| `similarity` | `BM25` / `boolean` / `classic` | `BM25` | 相关性评分算法 |

**REST API 示例**

```bash
curl -X PUT "localhost:9200/articles" -H "Content-Type: application/json" -d '{
  "mappings": {
    "properties": {
      "title": {
        "type": "text",
        "analyzer": "ik_max_word",
        "search_analyzer": "ik_smart",
        "index_options": "offsets",
        "term_vector": "with_positions_offsets",
        "similarity": "BM25"
      },
      "content": {
        "type": "text",
        "analyzer": "standard",
        "norms": false
      }
    }
  }
}'
```

**注意事项**

- `fielddata: true` 占用堆内存，极易 OOM，应优先使用 keyword 子字段做聚合。
- `index_options: offsets` 存储词项偏移量，支持高亮和 fast vector highlighter。
- `term_vector` 与 `index_options` 配合使用，`with_positions_offsets` 支持最优的高亮性能。
- text 字段默认追加 `.keyword` 子字段（Dynamic Mapping 行为）。

---

### keyword

**概念定义**

keyword 类型用于精确值匹配、聚合、排序。写入时不经过分析器分词，整个字符串作为单个词项索引。适用于 ID、状态码、标签、邮箱等结构化数据。

**核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `ignore_above` | 正整数 | `2147483647` | 超过此长度的字符串不索引 |
| `normalizer` | 标准化器名称 | 无 | 索引前预处理（如小写化），不改变分词 |
| `doc_values` | `true` / `false` | `true` | 是否支持聚合/排序 |
| `eager_global_ordinals` | `true` / `false` | `false` | 是否预构建全局序数 |
| `index` | `true` / `false` | `true` | 是否可搜索 |
| `time_series_dimension` | `true` / `false` | `false` | 是否作为 TSDS 维度字段（8.0+） |

**REST API 示例**

```bash
# 1. keyword 字段定义
curl -X PUT "localhost:9200/orders" -H "Content-Type: application/json" -d '{
  "settings": {
    "analysis": {
      "normalizer": {
        "lowercase_normalizer": {
          "type": "custom",
          "filter": ["lowercase"]
        }
      }
    }
  },
  "mappings": {
    "properties": {
      "order_id": {
        "type": "keyword"
      },
      "status": {
        "type": "keyword",
        "ignore_above": 50,
        "eager_global_ordinals": true
      },
      "email": {
        "type": "keyword",
        "normalizer": "lowercase_normalizer",
        "ignore_above": 256
      }
    }
  }
}'

# 2. keyword 聚合查询
curl -X POST "localhost:9200/orders/_search" -H "Content-Type: application/json" -d '{
  "size": 0,
  "aggs": {
    "by_status": {
      "terms": { "field": "status" }
    }
  }
}'
```

**注意事项**

- `ignore_above` 针对的是 UTF-16 编码后的字符数（非字节数），中文一个字符算 1 个字符。
- normalizer 是 keyword 专有的轻量级处理器，类似 analyzer 但不分词，常用场景：小写化、去重音符号。
- `eager_global_ordinals` 在数据量大时显著增加 heap 使用，仅对高频聚合字段开启。

### 数值类型（long / integer / double / float）

**概念定义**

数值类型存储数字，支持范围查询、精确匹配、聚合、排序。Elasticsearch 8.x 支持八种数值类型，其中最常用的是 `long`、`integer`、`double`、`float`。

**类型对照表**

| ES 类型 | Java 类型 | 取值范围 | 精度 |
|---|---|---|---|
| `long` | `long` | -2^63 ~ 2^63-1 | 整数 |
| `integer` | `int` | -2^31 ~ 2^31-1 | 整数 |
| `short` | `short` | -32768 ~ 32767 | 整数 |
| `byte` | `byte` | -128 ~ 127 | 整数 |
| `double` | `double` | IEEE 754 双精度 | 15-17 位有效数字 |
| `float` | `float` | IEEE 754 单精度 | 6-9 位有效数字 |
| `half_float` | 半精度 | IEEE 754 半精度 | 3-4 位有效数字 |
| `scaled_float` | `double` | 按 scaling_factor 缩放 | 整数存储，避免浮点误差 |

**核心参数**

| 参数 | 适用类型 | 默认值 | 说明 |
|---|---|---|---|
| `coerce` | 全部 | `true` | 是否自动字符串转数字 |
| `doc_values` | 全部 | `true` | 是否支持聚合/排序 |
| `index` | 全部 | `true` | 是否可搜索 |
| `null_value` | 全部 | `null` | null 替换值 |
| `ignore_malformed` | 全部 | `false` | 是否忽略格式错误值 |
| `scaling_factor` | `scaled_float` | 无（必填） | 缩放因子，如 100 表示保留两位小数 |
| `time_series_dimension` | 全部 | `false` | TSDS 维度字段（8.0+） |

**REST API 示例**

```bash
curl -X PUT "localhost:9200/products" -H "Content-Type: application/json" -d '{
  "mappings": {
    "properties": {
      "id": {
        "type": "long"
      },
      "quantity": {
        "type": "integer",
        "null_value": 0
      },
      "price": {
        "type": "scaled_float",
        "scaling_factor": 100,
        "ignore_malformed": true
      },
      "rating": {
        "type": "float",
        "coerce": false
      },
      "discount": {
        "type": "double",
        "index": false
      }
    }
  }
}'

# 数值范围查询
curl -X POST "localhost:9200/products/_search" -H "Content-Type: application/json" -d '{
  "query": {
    "range": {
      "price": { "gte": 10.00, "lte": 99.99 }
    }
  }
}'
```

**注意事项**

- 金额字段优先使用 `scaled_float`，避免 `double` 的浮点精度问题。`scaling_factor: 100` 将 9.99 存储为 999。
- `coerce: false` 时，写入 `"123"` 到 integer 字段会报错，保证数据质量。
- `ignore_malformed: true` 时，格式错误的值会被静默忽略（不索引但不报错），适合脏数据场景。
- Dynamic Mapping 默认将整数推断为 `long`，浮点数推断为 `float`，可能造成类型过宽，建议显式声明。

### date

**概念定义**

date 类型存储日期时间，内部以 epoch millis（long）形式存储，支持多种格式的输入输出。ES 8.x 默认使用 `strict_date_optional_time` 格式，即 ISO 8601 格式。

**内置格式**

| 格式名 | 示例 | 说明 |
|---|---|---|
| `epoch_millis` | `1704067200000` | 毫秒时间戳 |
| `epoch_second` | `1704067200` | 秒时间戳 |
| `strict_date_optional_time` | `2024-01-01T12:00:00.000Z` | ISO 8601（默认） |
| `basic_date` | `20240101` | 紧凑日期 |
| `basic_date_time` | `20240101T120000.000Z` | 紧凑日期时间 |
| `yyyy-MM-dd HH:mm:ss` | `2024-01-01 12:00:00` | 自定义格式 |

**核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `format` | 格式字符串，`\|\|` 分隔多个 | `strict_date_optional_time\|\|epoch_millis` | 接受的日期格式 |
| `doc_values` | `true` / `false` | `true` | 是否支持聚合/排序 |
| `null_value` | 日期值 | `null` | null 替换值 |
| `ignore_malformed` | `true` / `false` | `false` | 是否忽略格式错误值 |

**REST API 示例**

```bash
curl -X PUT "localhost:9200/events" -H "Content-Type: application/json" -d '{
  "mappings": {
    "properties": {
      "created_at": {
        "type": "date",
        "format": "yyyy-MM-dd HH:mm:ss||yyyy-MM-dd||epoch_millis"
      },
      "updated_at": {
        "type": "date",
        "null_value": "1970-01-01T00:00:00.000Z"
      }
    }
  }
}'

# date range 查询
curl -X POST "localhost:9200/events/_search" -H "Content-Type: application/json" -d '{
  "query": {
    "range": {
      "created_at": {
        "gte": "2024-01-01",
        "lte": "2024-12-31",
        "format": "yyyy-MM-dd"
      }
    }
  }
}'

# date histogram 聚合
curl -X POST "localhost:9200/events/_search" -H "Content-Type: application/json" -d '{
  "size": 0,
  "aggs": {
    "events_per_day": {
      "date_histogram": {
        "field": "created_at",
        "calendar_interval": "day"
      }
    }
  }
}'
```

**注意事项**

- 多个格式用 `||` 分隔，ES 按顺序尝试匹配，靠前的优先。
- 自定义格式前加 `strict_` 前缀会强制校验，如 `strict_yyyy-MM-dd` 拒绝 `"2024-01-01 12:00:00"`。
- 时区处理：搜索时用 `time_zone` 参数指定时区，聚合时日期直方图同样支持 `time_zone`。
- 推荐使用 `epoch_millis` 作为 Java 端与 ES 交互的统一格式，避免时区歧义。

### boolean

**概念定义**

boolean 类型存储真/假值，接受 `true`、`false`，以及字符串 `"true"`、`"false"`。内部以倒排索引的 `T` / `F` 词项存储。

**核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `doc_values` | `true` / `false` | `true` | 是否支持聚合/排序 |
| `index` | `true` / `false` | `true` | 是否可搜索 |
| `null_value` | `true` / `false` / `null` | `null` | null 替换值 |

**REST API 示例**

```bash
curl -X PUT "localhost:9200/users" -H "Content-Type: application/json" -d '{
  "mappings": {
    "properties": {
      "is_active": {
        "type": "boolean"
      },
      "is_deleted": {
        "type": "boolean",
        "null_value": false
      }
    }
  }
}'

# term 查询
curl -X POST "localhost:9200/users/_search" -H "Content-Type: application/json" -d '{
  "query": {
    "term": { "is_active": true }
  }
}'
```

**注意事项**

- 写入时 `"true"` / `"false"`（字符串）会被自动转换，`coerce` 参数对 boolean 不生效。
- 写入 `0` / `1` 或 `"0"` / `"1"` 不会自动转换，会报错。
- terms 聚合时，key 为 `0`（false）和 `1`（true）。

### geo_point / geo_shape

**概念定义**

`geo_point` 存储经纬度坐标点，`geo_shape` 存储任意地理形状（点、线、多边形、多点等）。两者均支持地理空间查询：距离过滤、边界框、多边形包含等。

**geo_point 核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `ignore_malformed` | `true` / `false` | `false` | 是否忽略格式错误值 |
| `null_value` | 坐标值 | `null` | null 替换值 |

**geo_shape 核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `orientation` | `right` / `left` / `ccw` / `cw` | `right` | 多边形顶点顺序约定 |
| `ignore_malformed` | `true` / `false` | `false` | 是否忽略格式错误值 |
| `ignore_z_value` | `true` / `false` | `true` | 是否忽略三维坐标的 Z 值 |

**REST API 示例**

```bash
curl -X PUT "localhost:9200/places" -H "Content-Type: application/json" -d '{
  "mappings": {
    "properties": {
      "location": {
        "type": "geo_point"
      },
      "service_area": {
        "type": "geo_shape"
      }
    }
  }
}'

# 写入 geo_point（四种格式均可）
curl -X POST "localhost:9200/places/_doc" -H "Content-Type: application/json" -d '{
  "name": "Central Park",
  "location": { "lat": 40.785091, "lon": -73.968285 }
}'

# 写入 geo_shape
curl -X POST "localhost:9200/places/_doc" -H "Content-Type: application/json" -d '{
  "name": "Delivery Zone A",
  "service_area": {
    "type": "polygon",
    "coordinates": [[[-73.99,40.75],[-73.97,40.75],[-73.97,40.77],[-73.99,40.77],[-73.99,40.75]]]
  }
}'

# geo_distance 查询
curl -X POST "localhost:9200/places/_search" -H "Content-Type: application/json" -d '{
  "query": {
    "geo_distance": {
      "distance": "5km",
      "location": { "lat": 40.78, "lon": -73.97 }
    }
  }
}'

# geo_bounding_box 查询
curl -X POST "localhost:9200/places/_search" -H "Content-Type: application/json" -d '{
  "query": {
    "geo_bounding_box": {
      "location": {
        "top_left": { "lat": 40.80, "lon": -74.00 },
        "bottom_right": { "lat": 40.74, "lon": -73.95 }
      }
    }
  }
}'
```

**注意事项**

- geo_point 支持四种输入格式：对象 `{lat, lon}`、数组 `[lon, lat]`、WKT `POINT(...)`、geohash。
- 数组格式中顺序是 `[lon, lat]`（经度在前），与 GeoJSON 的 `[lon, lat]` 一致，不要与对象格式的 `{lat, lon}` 混淆。
- geo_shape 内部使用 BKD 树索引，适合大规模地理形状查询。
- 距离计算默认使用 `arc`（球面弧长），可切换为 `plane`（平面计算，速度快但精度低）。

### ip

**概念定义**

ip 类型存储 IPv4 和 IPv6 地址，支持 CIDR 范围查询。内部以二进制形式存储，查询效率高。

**核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `doc_values` | `true` / `false` | `true` | 是否支持聚合/排序 |
| `null_value` | IP 地址 | `null` | null 替换值 |
| `ignore_malformed` | `true` / `false` | `false` | 是否忽略格式错误值 |

**REST API 示例**

```bash
curl -X PUT "localhost:9200/logs" -H "Content-Type: application/json" -d '{
  "mappings": {
    "properties": {
      "client_ip": {
        "type": "ip",
        "ignore_malformed": true
      },
      "server_ip": {
        "type": "ip"
      }
    }
  }
}'

# 写入
curl -X POST "localhost:9200/logs/_doc" -H "Content-Type: application/json" -d '{
  "client_ip": "192.168.1.100",

# CIDR 范围查询

```

**注意事项**

### binary

**概念定义**

binary 类型用于存储 Base64 编码的二进制数据，不索引、不可搜索、不聚合。仅用于在 `_source` 中保留原始数据，供应用层读取后自行处理。

**核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `doc_values` | `true` / `false` | `false` | 固定为 false |
| `store` | `true` / `false` | `false` | 是否独立存储 |

**REST API 示例**

```bash
curl -X PUT "localhost:9200/files" -H "Content-Type: application/json" -d '{
  "mappings": {
    "properties": {
      "name": { "type": "keyword" },
      "thumbnail": { "type": "binary" }
    }
  }
}'

# 写入（Base64 编码后的二进制数据）
curl -X POST "localhost:9200/files/_doc" -H "Content-Type: application/json" -d '{
  "name": "icon.png",
  "thumbnail": "iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mNk..."
}'
```

**注意事项**

- binary 字段不可搜索、不可聚合、不可排序，仅用于存储和回显。

### nested / join

**概念定义**

`nested` 类型用于索引对象数组，保持数组元素间的独立性，避免 `object` 类型的扁平化导致跨对象匹配。`join` 类型用于在同一索引中定义父子文档关系，支持 `has_child`、`has_parent` 查询。

**nested 核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `dynamic` | `true` / `false` / `strict` | `true` | 嵌套对象内部字段的动态行为 |
| `properties` | 字段定义 | 无 | 嵌套对象的字段映射 |

**join 核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `relations` | `{ "parent": "child" }` 格式 | 无（必填） | 定义父子关系 |
| `eager_global_ordinals` | `true` / `false` | `false` | 是否预构建全局序数 |

**REST API 示例**

```bash
# 1. nested 类型
curl -X PUT "localhost:9200/orders" -H "Content-Type: application/json" -d '{
  "mappings": {
    "properties": {
      "items": {
        "type": "nested",
        "properties": {
          "sku":    { "type": "keyword" },
          "qty":    { "type": "integer" },
          "price":  { "type": "double" }
        }
      }
    }
  }
}'

# nested 查询：每个 item 独立匹配
curl -X POST "localhost:9200/orders/_search" -H "Content-Type: application/json" -d '{
  "query": {
    "nested": {
      "path": "items",
      "query": {
        "bool": {
          "must": [
            { "term":  { "items.sku": "A001" } },
            { "range": { "items.qty": { "gte": 5 } } }
          ]
        }
      }
    }
  }
}'

# 2. join 类型
curl -X PUT "localhost:9200/departments" -H "Content-Type: application/json" -d '{
  "mappings": {
    "properties": {
      "my_join_field": {
        "type": "join",
        "relations": {
          "department": "employee"
        }
      },
      "name": { "type": "text" }
    }
  }
}'

# 写入父文档
curl -X POST "localhost:9200/departments/_doc/1" -H "Content-Type: application/json" -d '{
  "name": "Engineering",
  "my_join_field": "department"
}'

# 写入子文档（routing 必须指向父文档 ID）
curl -X POST "localhost:9200/departments/_doc/2?routing=1" -H "Content-Type: application/json" -d '{
  "name": "Alice",
  "my_join_field": { "name": "employee", "parent": "1" }
}'

# has_child 查询
curl -X POST "localhost:9200/departments/_search" -H "Content-Type: application/json" -d '{
  "query": {
    "has_child": {
      "type": "employee",
      "query": { "match": { "name": "Alice" } }
    }
  }
}'
```

**注意事项**

- nested 文档在内部是独立的 Lucene 文档，查询时需使用 `nested` query/path 包裹，否则跨对象匹配不准确。
- 每个 nested 对象都会增加一个 Lucene 文档，大量 nested 会导致写入和查询性能下降。
- join 父子文档必须在同一分片（通过 routing 保证），因此子文档写入/查询/删除必须携带 `routing=parent_id`。
- join 类型在单个分片内最多支持有限数量的子文档，大量子文档场景优先考虑宽表或 nested 替代。

### dense_vector / sparse_vector

**概念定义**

`dense_vector` 存储固定维度的浮点向量，用于 kNN 向量相似度搜索（8.0+ 原生支持）。`sparse_vector` 存储稀疏向量（大部分维度为 0），用于稀疏向量检索，8.x 中已被 `rank_features` 替代，但仍保留兼容。

**核心参数（dense_vector）**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `dims` | 正整数 | 无（必填） | 向量维度，最大 4096 |
| `index` | `true` / `false` | `true` | 是否可搜索 |
| `similarity` | `l2_norm` / `dot_product` / `cosine` / `max_inner_product` | `l2_norm` | 相似度算法 |
| `index_options` | `hnsw` 配置对象 | 默认 HNSW 参数 | HNSW 图索引参数 |
| `element_type` | `float` / `byte` | `float` | 向量元素类型（8.9+） |

**index_options 子参数（HNSW）**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `type` | `hnsw` | `hnsw` | 索引类型 |
| `m` | 正整数 | 16 | 每层最大连接数 |
| `ef_construction` | 正整数 | 100 | 构建时搜索宽度 |

**REST API 示例**

```bash
# 1. dense_vector 定义
curl -X PUT "localhost:9200/images" -H "Content-Type: application/json" -d '{
  "mappings": {
    "properties": {
      "title": { "type": "text" },
      "embedding": {
        "type": "dense_vector",
        "dims": 768,
        "similarity": "cosine",
        "index": true,
        "index_options": {
          "type": "hnsw",
          "m": 16,
          "ef_construction": 100
        }
      }
    }
  }
}'

# 2. 写入向量
curl -X POST "localhost:9200/images/_doc" -H "Content-Type: application/json" -d '{
  "title": "sunset photo",
  "embedding": [0.12, -0.34, 0.56, ...]
}'

# 3. kNN 搜索（8.0+ 原生语法）
curl -X POST "localhost:9200/images/_search" -H "Content-Type: application/json" -d '{
  "knn": {
    "field": "embedding",
    "query_vector": [0.11, -0.33, 0.55, ...],
    "k": 10,
    "num_candidates": 100
  }
}'

# 4. 混合搜索（kNN + 关键词过滤）
curl -X POST "localhost:9200/images/_search" -H "Content-Type: application/json" -d '{
  "knn": {
    "field": "embedding",
    "query_vector": [0.11, -0.33, 0.55, ...],
    "k": 10,
    "num_candidates": 100,
    "filter": {
      "term": { "category": "landscape" }
    }
  }
}'
```

**注意事项**

- `dims` 必须在创建索引时确定且不可修改，务必与 Embedding 模型输出维度一致。
- `cosine` 相似度要求向量为 L2 归一化向量；`dot_product` 等价于对归一化向量使用余弦相似度。
- `m` 和 `ef_construction` 越大，召回率越高，但索引构建时间和内存占用越大。
- 8.9+ 支持 `element_type: byte`，将向量量化为 8 位整数，内存节省 4 倍，但精度略有损失。
- 8.15+ 支持 `int4` / `int8` 量化，进一步压缩向量存储。

## Analyzer 分析器

### Character Filter

**概念定义**

Character Filter 是分析器流水线的第一环节，在分词前对原始文本进行字符级预处理（替换、删除、映射）。一个 Analyzer 可配置零到多个 Character Filter，按声明顺序执行。

**内置 Character Filter**

| 名称 | 功能 | 核心参数 |
|---|---|---|
| `html_strip` | 去除 HTML 标签，解码 HTML 实体 | `escaped_tags`（保留的标签数组） |
| `mapping` | 字符一对一映射替换 | `mappings`（映射规则数组），`mappings_path`（外部规则文件） |
| `pattern_replace` | 正则替换 | `pattern`（正则），`replacement`（替换字符串） |

**REST API 示例**

```bash
# 1. html_strip
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "char_filter": ["html_strip"],
  "text": "<p>Hello <b>World</b> &amp; ES</p>"
}'

# 2. mapping 字符映射
curl -X PUT "localhost:9200/_settings" -H "Content-Type: application/json" -d '{
  "analysis": {
    "char_filter": {
      "my_char_filter": {
        "type": "mapping",
        "mappings": ["=> => ", "& => and", ":) => _happy_"]
      }
    }
  }
}'

# 3. pattern_replace
curl -X PUT "localhost:9200/_settings" -H "Content-Type: application/json" -d '{
  "analysis": {
    "char_filter": {
      "remove_special": {
        "type": "pattern_replace",
        "pattern": "[^a-zA-Z0-9\\s]",
        "replacement": ""
      }
    }
  }
}'
```

**注意事项**

- Character Filter 在 Tokenizer 之前执行，操作的是原始字符串而非词项。
- `mapping` 的映射规则是顺序敏感的，`"=> => "` 将箭头替换为空格，`"& => and"` 将 `&` 替换为 `and`。
- `pattern_replace` 的 `replacement` 支持 `$1` 等捕获组引用。
- `html_strip` 的 `escaped_tags` 参数可保留部分标签不被剥离，如 `"escaped_tags": ["b"]` 保留 `<b>` 标签。

---

### Tokenizer

**概念定义**

Tokenizer 是分析器流水线的核心环节，在 Character Filter 之后执行，将字符串切分为词项（Term）流。每个 Analyzer 必须有且仅有一个 Tokenizer。

**内置 Tokenizer 速览**

| Tokenizer | 分词策略 | 典型输入 | 典型输出 |
|---|---|---|---|
| `standard` | Unicode 文本分割算法，按词边界切分 | `"Hello World!"` | `["hello", "world"]` |
| `letter` | 按非字母字符切分 | `"hello-world"` | `["hello", "world"]` |
| `lowercase` | 同 letter + 小写化 | `"Hello World"` | `["hello", "world"]` |
| `whitespace` | 按空白字符切分 | `"Hello World"` | `["Hello", "World"]` |
| `keyword` | 不切分，整体输出 | `"Hello World"` | `["Hello World"]` |
| `pattern` | 正则切分 | `"a,b;c"` | 按正则输出 |
| `uax_url_email` | 类似 standard，但保留 URL/Email 完整性 | `"email@x.com"` | `["email@x.com"]` |
| `path_hierarchy` | 按路径层级切分 | `"/a/b/c"` | `["/a", "/a/b", "/a/b/c"]` |
| `ngram` | N-gram 切分 | `"abc"` | `["a","ab","b","bc","c"]` |
| `edge_ngram` | 前缀 N-gram 切分 | `"abc"` | `["a","ab","abc"]` |
| `ik_max_word` | 细粒度中文分词（IK 插件） | `"中华人民共和国"` | `["中华人民共和国","中华人民","中华","华人","人民共和国","人民","共和国","共和","国"]` |
| `ik_smart` | 粗粒度中文分词（IK 插件） | `"中华人民共和国"` | `["中华人民共和国"]` |

**核心参数（通用）**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `type` | Tokenizer 名称 | 无（必填） | Tokenizer 类型 |
| `min_gram` | 正整数 | `1` | ngram/edge_ngram 最小长度 |
| `max_gram` | 正整数 | `2` | ngram/edge_ngram 最大长度 |
| `token_chars` | 字符类别数组 | `[]` | ngram/edge_ngram 参与分词的字符类别 |

**REST API 示例**

```bash
# 1. 内置 Tokenizer 测试
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "tokenizer": "standard",
  "text": "The quick brown fox jumps over the lazy dog."
}'

# 2. 自定义 pattern Tokenizer
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "tokenizer": {
    "type": "pattern",
    "pattern": ","
  },
  "text": "apple,banana,cherry"
}'

# 3. 自定义 ngram Tokenizer
curl -X PUT "localhost:9200/_settings" -H "Content-Type: application/json" -d '{
  "analysis": {
    "tokenizer": {
      "my_ngram": {
        "type": "ngram",
        "min_gram": 2,
        "max_gram": 4,
        "token_chars": ["letter", "digit"]
      }
    }
  }
}'
```

**注意事项**

- `standard` Tokenizer 基于 Unicode 标准文本分割算法（UAX #29），处理多语言文本效果较好。
- `ngram` / `edge_ngram` 会产生大量词项，索引膨胀严重，务必限制 `min_gram` / `max_gram` 范围。
- `edge_ngram` 常用于自动补全（autocomplete）场景，仅生成前缀 N-gram。
- `path_hierarchy` 对路径 `/a/b/c` 生成 `["/a", "/a/b", "/a/b/c"]`，实现路径前缀匹配。

### Token Filter

**概念定义**

Token Filter 在 Tokenizer 之后执行，对词项流进行增删改：添加同义词、删除停用词、小写化、词干提取、拼音转换等。一个 Analyzer 可配置零到多个 Token Filter，按声明顺序执行。

**内置 Token Filter 分类**

| 类别 | 典型 Filter | 功能 |
|---|---|---|
| 大小写/标准化 | `lowercase`, `uppercase` | 大小写转换 |
| 停用词 | `stop` | 移除停用词（the, a, is 等） |
| 词干提取 | `stemmer`, `porter_stem`, `kstem` | 英文词干提取 |
| 词形还原 | `hunspell` | 基于词典的词形还原 |
| 同义词 | `synonym`, `synonym_graph` | 同义词扩展 |
| 拼音 | `pinyin` | 汉字转拼音（IK 插件） |
| N-gram | `ngram`, `edge_ngram` | 词项级 N-gram |
| 去重 | `unique` | 移除重复词项 |
| 长度过滤 | `length`, `truncate` | 按长度过滤/截断 |
| 词项限制 | `limit_token_count` | 限制词项数量 |
| 条件处理 | `condition` | 按条件应用子 Filter |
| 保护词 | `keyword_marker` | 标记不处理的词 |
| 其他 | `reverse`, `shingle`, `remove_duplicates` | 反转、shingle、去重 |

**REST API 示例**

```bash
# 1. 内置 Token Filter 测试
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "tokenizer": "standard",
  "filter": ["lowercase", "stop", "stemmer"],
  "text": "The Quick Brown Foxes Are Jumping"
}'

# 2. 自定义 stop filter
curl -X PUT "localhost:9200/my_index" -H "Content-Type: application/json" -d '{
  "settings": {
    "analysis": {
      "filter": {
        "my_stop": {
          "type": "stop",
          "stopwords": ["the", "a", "an", "is", "are"]
        },
        "my_stemmer": {
          "type": "stemmer",
          "language": "english"
        },
        "my_length": {
          "type": "length",
          "min": 2,
          "max": 20
        }
      }
    }
  }
}'

# 3. shingle filter（生成相邻词组合）
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "tokenizer": "standard",
  "filter": [
    { "type": "shingle", "min_shingle_size": 2, "max_shingle_size": 3, "output_unigrams": false }
  ],
  "text": "quick brown fox jumps"
}'
```

**注意事项**

- Filter 顺序至关重要：`lowercase` 应在 `stop` 之前，否则停用词可能因大小写不匹配而未被移除。
- `synonym` 与 `synonym_graph` 的区别：前者在分词后展开平级同义词，后者保留同义词图谱结构，后者更适合多词同义词（如 "elasticsearch" -> "elastic search"）。
- `stemmer` 的词干提取是启发式算法（如 `jumping` -> `jump`），`hunspell` 是词典驱动，精度更高但速度慢。
- `ngram` Token Filter 与 `ngram` Tokenizer 的区别：前者在词项级别生成 N-gram，后者在字符级别生成 N-gram。

### 分析过程（_analyze API）

**概念定义**

`_analyze` API 用于测试和验证分析过程，可指定任意 Tokenizer、Token Filter、Character Filter 组合，或使用已有索引的字段分析器，返回每个词项的详细信息（位置、偏移量、类型等）。

**REST API 示例**

```bash
# 1. 使用指定分析器
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "standard",
  "text": "The quick brown fox."
}'

# 2. 使用自定义 Tokenizer + Filter 组合
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "tokenizer": "ik_max_word",
  "filter": ["lowercase"],
  "text": "中华人民共和国"
}'

# 3. 使用已有索引的字段分析器
curl -X POST "localhost:9200/articles/_analyze" -H "Content-Type: application/json" -d '{
  "field": "title",
  "text": "Elasticsearch 8.x 分词与映射"
}'

# 4. 分别指定 Char Filter、Tokenizer、Filter
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "char_filter": ["html_strip"],
  "tokenizer": "standard",
  "filter": ["lowercase", "stop"],
  "text": "<p>The Quick Brown Fox</p>"
}'

# 5. 返回 explain 详细信息（标记每个 filter 的处理结果）
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "tokenizer": "standard",
  "filter": ["lowercase", "asciifolding"],
  "text": "Café au Lait",
  "explain": true
}'
```

**返回字段说明**

| 字段 | 说明 |
|---|---|
| `token` | 词项文本 |
| `start_offset` | 词项在原文中的起始偏移量 |
| `end_offset` | 词项在原文中的结束偏移量 |
| `type` | 词项类型（`<ALPHANUM>`, `<NUM>`, `<HANGUL>` 等） |
| `position` | 词项在词项流中的位置 |

**注意事项**

- `explain: true` 会展示每个 Token Filter 处理前后的词项变化，对调试复杂分析器链极有帮助。
- 使用 `_analyze` 测试时，Character Filter 的效果不会直接展示在输出中，但可通过 `start_offset` / `end_offset` 的变化推断。
- 搜索时分析器与索引时分析器可能不同，建议用 `_analyze` 分别验证两端效果。

## 内置分词器

### standard

**概念定义**

standard 是 ES 默认分词器，基于 Unicode 文本分割算法（UAX #29），按词边界切分，同时移除标点符号并小写化。适用于大多数印欧语系文本。

**组成**

- Tokenizer: `standard`
- Token Filter: `lowercase`

**核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `max_token_length` | 正整数 | 255 | 最大词项长度，超长截断 |
| `stopwords` | 停用词列表或 `_none_` | `_none_` | 停用词（默认不启用） |

**REST API 示例**

```bash
# 1. 默认 standard 分析器
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "standard",
  "text": "The 2 QUICK Brown-Foxes, bon appétit! Price: $99.99"
}'

# 2. 自定义 standard 分析器（带停用词）
curl -X PUT "localhost:9200/my_index" -H "Content-Type: application/json" -d '{
  "settings": {
    "analysis": {
      "analyzer": {
        "my_standard": {
          "type": "standard",
          "stopwords": ["the", "a", "an"],
          "max_token_length": 100
        }
      }
    }
  }
}'
```

**注意事项**

- standard 对中文无效，会将每个汉字当作独立词项（如 `"你好"` -> `["你", "好"]`），中文场景需用 IK 分词器。
- 英文连字符（`-`）会被视为词边界，`"Brown-Foxes"` 切分为 `["brown", "foxes"]`。
- 邮箱地址和 URL 会被部分切分，如需保留完整 URL/Email 使用 `uax_url_email` Tokenizer。

---

### simple

**概念定义**

simple 分词器按非字母字符切分文本，并将所有词项小写化。比 standard 更简单，不识别数字和标点，仅保留字母序列。

**组成**

- Tokenizer: `lowercase`（等价于 letter + lowercase）

**REST API 示例**

```bash
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "simple",
  "text": "The 2 QUICK Brown-Foxes, bon appétit! Price: $99.99"
}'
# 输出: ["the", "quick", "brown", "foxes", "bon", "appétit", "price"]
```

**注意事项**

- 数字被完全移除，`"2"` 不产生任何词项。
- 非 ASCII 字母（如 `é`）被保留，不进行 Unicode 规范化。
- 适合仅需字母匹配的简单场景，如标签名、类别名。

---

### whitespace

**概念定义**

whitespace 分词器按空白字符（空格、制表符、换行符）切分文本，不做任何其他处理（不小写化、不去标点）。适合已预处理的结构化文本。

**组成**

- Tokenizer: `whitespace`

**REST API 示例**

```bash
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "whitespace",
  "text": "The 2 QUICK Brown-Foxes, bon appétit! Price: $99.99"
}'
# 输出: ["The", "2", "QUICK", "Brown-Foxes,", "bon", "appétit!", "Price:", "$99.99"]
```

**注意事项**

- 标点符号粘连在词项上（如 `"Brown-Foxes,"` 包含逗号），不做移除。
- 大小写保留原样，适合精确匹配场景。
- 常与 `lowercase` Token Filter 组合使用，实现按空白分词 + 小写化。

---

### stop

**概念定义**

stop 分词器在 standard 基础上增加停用词过滤，移除 the、a、is 等高频无实义词。等同于 `standard` + `stop` Token Filter。

**组成**

- Tokenizer: `standard`
- Token Filter: `lowercase` + `stop`（默认停用词为 `_english_`）

**核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `stopwords` | 停用词列表或 `_english_` / `_none_` / 语言值 | `_english_` | 停用词集合 |
| `stopwords_path` | 文件路径 | 无 | 外部停用词文件 |

**REST API 示例**

```bash
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "stop",
  "text": "The quick brown fox jumps over the lazy dog"
}'
# 输出: ["quick", "brown", "fox", "jumps", "over", "lazy", "dog"]
# "The" 和 "the" 被移除

# 自定义停用词
curl -X PUT "localhost:9200/my_index" -H "Content-Type: application/json" -d '{
  "settings": {
    "analysis": {
      "analyzer": {
        "my_stop": {
          "type": "stop",
          "stopwords": ["a", "an", "the", "is", "are", "was", "were"]
        }
      }
    }
  }
}'
```

**注意事项**

- 默认使用 `_english_` 停用词列表，包含约 50 个英文常用停用词。
- 中文场景需自定义停用词列表（如 `"的"`、`"了"`、`"是"`），IK 分词器支持 `ext_stopwords` 配置。
- 停用词过滤发生在 lowercase 之后，因此停用词列表应使用小写形式。

---

### keyword

**概念定义**

keyword 分词器是"不分析"的分析器，将整个输入文本作为单个词项输出。用于需要精确匹配的场景（如 ID、标签、状态码）。

**组成**

- Tokenizer: `keyword`

**REST API 示例**

```bash
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "keyword",
  "text": "The Quick Brown Fox"
}'
# 输出: ["The Quick Brown Fox"]  （单个词项）
```

**注意事项**

- keyword 分析器与 keyword 字段类型不同：前者是分析器，后者是字段类型。
- keyword 字段类型通常使用 `standard` 分析器或不分析，但可通过 `analyzer` 参数指定 keyword 分析器实现整体匹配。
- 常与 keyword 字段类型配合，用于 `term` 精确查询。

---

### pattern

**概念定义**

pattern 分词器使用正则表达式切分文本，默认 Pattern 为 `\W+`（非单词字符）。支持完全自定义正则，灵活度极高。

**组成**

- Tokenizer: `pattern`（默认 `\W+`）
- Token Filter: `lowercase`

**核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `pattern` | 正则表达式 | `\W+` | 切分正则 |
| `flags` | 正则标志 | 无 | `CASE_INSENSITIVE`, `COMMENTS`, `MULTILINE`, `DOTALL`, `UNICODE_CASE` |
| `lowercase` | `true` / `false` | `true` | 是否小写化 |
| `stopwords` | 停用词列表 | `_none_` | 停用词 |

**REST API 示例**

```bash
# 1. 默认 pattern（按非单词字符切分）
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "pattern",
  "text": "foo,bar;baz:qux"
}'
# 输出: ["foo", "bar", "baz", "qux"]

# 2. 自定义 pattern（按逗号切分）
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "tokenizer": {
    "type": "pattern",
    "pattern": ",\\s*"
  },
  "text": "apple, banana, cherry, date"
}'
# 输出: ["apple", "banana", "cherry", "date"]

# 3. 捕获组用作词项
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "tokenizer": {
    "type": "pattern",
    "pattern": "([^,]+)",
    "group": 1
  },
  "text": "apple, banana, cherry"
}'
```

**注意事项**

- 默认 `pattern` 为 `\W+`，即一个或多个非单词字符作为分隔符。
- 使用捕获组 `group` 参数时，仅捕获组匹配的内容成为词项（而非分隔符之间的内容）。
- Java 正则表达式语法，特殊字符需转义（如 `\s` 需要写成 `\\s`）。
- Pattern 太复杂会影响性能，建议对极大规模日志解析使用 Ingest Pipeline 预处理。

---

### language（多语言分词器）

**概念定义**

language 分析器是一组针对特定语言的预配置分析器，内置了该语言的停用词、词干提取器（Stemmer），以及词形还原规则。ES 8.x 支持 30+ 语言。

**支持的语言（部分）**

| 语言 | 分析器名 | 词干提取算法 |
|---|---|---|
| 英语 | `english` | Porter Stemmer |
| 法语 | `french` | French Light Stemmer |
| 德语 | `german` | German Light Stemmer |
| 西班牙语 | `spanish` | Spanish Light Stemmer |
| 俄语 | `russian` | Russian Light Stemmer |
| 阿拉伯语 | `arabic` | Arabic Stemmer |
| 日语 | `cjk` | CJK Bigram（无词干提取） |
| 韩语 | `cjk` | CJK Bigram（无词干提取） |
| 中文 | — | 无内置，需 IK 插件 |

**REST API 示例**

```bash
# 1. 英语分析器
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "english",
  "text": "The quick brown foxes are running quickly"
}'
# 输出: ["quick", "brown", "fox", "run", "quickli"]
# foxes -> fox, running -> run, quickly -> quickli

# 2. 法语分析器
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "french",
  "text": "Les chats mangent les poissons"
}'

# 3. 自定义语言分析器（覆盖停用词）
curl -X PUT "localhost:9200/my_index" -H "Content-Type: application/json" -d '{
  "settings": {
    "analysis": {
      "filter": {
        "english_stop": {
          "type": "stop",
          "stopwords": ["the", "a", "an"]
        },
        "english_stemmer": {
          "type": "stemmer",
          "language": "light_english"
        }
      },
      "analyzer": {
        "my_english": {
          "tokenizer": "standard",
          "filter": ["english_stop", "english_stemmer", "lowercase"]
        }
      }
    }
  }
}'
```

**注意事项**

- `cjk` 分析器对中日韩文本使用 Bigram 切分，效果不如专用分词器（IK、Kuromoji、Nori）。
- 词干提取器（Stemmer）是启发式算法，可能产生非单词（如 `quickli`），这不影响搜索匹配。
- 如需精确词形还原，使用 `hunspell` Token Filter 配合词典文件。
- 中文、日文、韩文不在 language 分析器支持列表中，需额外安装对应插件。

## 中文分词

### IK 分词器安装与配置

**概念定义**

IK Analysis 是 Elasticsearch 最常用的中文分词插件，基于词典和规则进行中文分词，支持细粒度（ik_max_word）和粗粒度（ik_smart）两种模式。ES 8.x 需安装对应版本的 IK 插件。

**安装步骤**

```bash
# 1. 在线安装（推荐）
./bin/elasticsearch-plugin install https://get.infini.cloud/elasticsearch/analysis-ik/8.x.x

# 2. 离线安装（下载 zip 后）
./bin/elasticsearch-plugin install file:///path/to/analysis-ik-8.x.x.zip

# 3. Docker 安装
docker exec -it es8 elasticsearch-plugin install \
  https://get.infini.cloud/elasticsearch/analysis-ik/8.x.x

# 4. 重启 ES 节点
systemctl restart elasticsearch

# 5. 验证安装
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "ik_max_word",
  "text": "中华人民共和国"
}'
```

**配置文件结构**

```
config/analysis-ik/
├── IKAnalyzer.cfg.xml        # 主配置文件
├── main.dic                  # 主词典
├── quantifier.dic            # 量词词典
├── suffix.dic                # 后缀词典
├── stopword.dic              # 停用词词典
├── custom/                   # 自定义词典目录
│   └── mydict.dic
└── extra_stopword.dic        # 扩展停用词
```

**核心配置（IKAnalyzer.cfg.xml）**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE properties SYSTEM "http://java.sun.com/dtd/properties.dtd">
<properties>
    <comment>IK Analyzer 扩展配置</comment>
    <!-- 扩展词典 -->
    <entry key="ext_dict">custom/mydict.dic</entry>
    <!-- 扩展停用词 -->
    <entry key="ext_stopwords">extra_stopword.dic</entry>
    <!-- 远程词典（热更新） -->
    <entry key="remote_ext_dict">http://your-server.com/ik/dict.txt</entry>
    <!-- 远程停用词 -->
    <entry key="remote_ext_stopwords">http://your-server.com/ik/stop.txt</entry>
</properties>
```

**注意事项**

- IK 插件版本必须与 ES 版本严格匹配，否则节点无法启动。
- 集群环境下每个节点都需安装 IK 插件，且配置文件保持一致。
- 修改 `IKAnalyzer.cfg.xml` 或自定义词典后需重启 ES 节点（热更新词典除外）。
- Docker 环境下，建议将词典目录挂载为 Volume 以便持久化修改。

### ik_smart vs ik_max_word

**概念定义**

`ik_smart` 是粗粒度分词模式，采用最少切分策略，输出最少的词项组合。`ik_max_word` 是细粒度分词模式，穷举所有可能的词项组合，输出最丰富的词项。

**对比示例**

| 输入 | ik_smart 输出 | ik_max_word 输出 |
|---|---|---|
| `中华人民共和国` | `["中华人民共和国"]` | `["中华人民共和国","中华人民","中华","华人","人民共和国","人民","共和国","共和","国"]` |
| `乒乓球拍卖完了` | `["乒乓球","拍卖","完了"]` | `["乒乓球","乒乓","球拍","拍卖","拍","卖","完了","完了"]` |
| `北京大学生前来应聘` | `["北京","大学生","前来","应聘"]` | `["北京","大学","大学生","学生","生前","前来","应聘"]` |

**REST API 示例**

```bash
# ik_smart 分析
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "ik_smart",
  "text": "乒乓球拍卖完了"
}'

# ik_max_word 分析
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "ik_max_word",
  "text": "乒乓球拍卖完了"
}'
```

**使用策略建议**

| 场景 | 推荐分析器 | 原因 |
|---|---|---|
| 索引时 | `ik_max_word` | 尽可能多切分词项，提高召回率 |
| 搜索时 | `ik_smart` | 减少词项数量，提高查询精度和性能 |
| 单字段搜索 | `ik_max_word` | 兼顾召回率和精度 |
| 聚合（如标签云） | `ik_smart` | 词项粒度合理，避免过度拆分 |

**注意事项**

- `ik_smart` 的切分结果受词典质量影响较大，缺少的词汇会导致切分不准确。
- `ik_max_word` 会产生大量非语义词项（如 `"共和"`、`"国"`），可能引入噪音匹配。
- 歧义消解：`ik_smart` 使用最大概率路径算法，`ik_max_word` 输出所有可能路径。
- 推荐组合：索引时 `ik_max_word` + 搜索时 `ik_smart`，在 Mapping 中分别指定 `analyzer` 和 `search_analyzer`。

---

### 自定义词典

**概念定义**

IK 分词器的分词效果依赖于词典质量。自定义词典允许添加 IK 默认词典未覆盖的词汇（如专业术语、品牌名、新词），确保分词准确。

**词典格式**

```
# 自定义词典文件（每行一个词，UTF-8 编码）
# 支持词性标注（可选）
人工智能
大模型
微服务
Spring Boot
Kubernetes
DevOps 3  # 数字表示词频（越高越优先）
```

**配置步骤**

1. 创建自定义词典文件

```bash
# 在 config/analysis-ik/custom/ 下创建词典文件
echo "微服务" >> config/analysis-ik/custom/mydict.dic
echo "大语言模型" >> config/analysis-ik/custom/mydict.dic
echo "Kubernetes" >> config/analysis-ik/custom/mydict.dic
```

2. 修改 IKAnalyzer.cfg.xml

```xml
<entry key="ext_dict">custom/mydict.dic</entry>
```

3. 重启 ES 节点

```bash
systemctl restart elasticsearch
```

4. 验证分词效果

```bash
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "ik_smart",
  "text": "大语言模型与微服务架构"
}'
```

**停用词配置**

```bash
# 创建停用词文件
echo "的" > config/analysis-ik/extra_stopword.dic
echo "了" >> config/analysis-ik/extra_stopword.dic
echo "是" >> config/analysis-ik/extra_stopword.dic
echo "在" >> config/analysis-ik/extra_stopword.dic

# 在 IKAnalyzer.cfg.xml 中引用
# <entry key="ext_stopwords">extra_stopword.dic</entry>
```

**注意事项**

- 词典文件必须使用 UTF-8 无 BOM 编码。
- 词频标注（数字）仅对 `ik_smart` 有影响，数字越大优先级越高，`ik_max_word` 忽略词频。
- 多个词典文件用分号分隔：`custom/dict1.dic;custom/dict2.dic`。
- 词典文件修改后必须重启 ES 节点（除非使用热更新）。

### 热更新词典

**概念定义**

IK 热更新词典允许在不重启 ES 节点的情况下，从远程 HTTP 服务器动态加载最新词典，支持增量更新，适用于需要频繁更新词汇的场景（如新闻热点词、网络新词）。

**配置步骤**

1. 准备远程词典文件（HTTP 可达）

```bash
# 远程词典格式（每行一个词，UTF-8）
# http://your-server.com/ik/dict.txt
大语言模型
AIGC
新质生产力
```

2. 修改 IKAnalyzer.cfg.xml

```xml
<entry key="remote_ext_dict">http://your-server.com/ik/dict.txt</entry>
<entry key="remote_ext_stopwords">http://your-server.com/ik/stop.txt</entry>
```

3. 重启 ES（首次加载）

**热更新机制**

- IK 每分钟检查一次远程词典的 `Last-Modified` 和 `ETag` HTTP 响应头。
- 若检测到变化，自动下载并重新加载词典，无需重启。
- 每个节点独立拉取远程词典，需保证远程服务器的高可用性。

**远程词典 HTTP 响应头要求**

| 响应头 | 必须 | 说明 |
|---|---|---|
| `Last-Modified` | 是 | 判断词典是否更新 |
| `ETag` | 否（推荐） | 辅助判断词典变更 |
| `Content-Type` | 否 | 建议 `text/plain; charset=UTF-8` |

**Nginx 配置示例**

```nginx
location /ik/dict.txt {
    alias /data/ik/dict.txt;
    add_header Content-Type "text/plain; charset=UTF-8";
    # Nginx 自动处理 Last-Modified 和 ETag
}
```

**注意事项**

- 仅 `remote_ext_dict` 和 `remote_ext_stopwords` 支持热更新，本地词典修改仍需重启。
- 热更新仅增量添加新词，不会删除已加载的旧词（如需删除需重启）。
- 远程服务器不可达时，IK 使用上次缓存的词典，不会影响分词服务。
- 集群环境下所有节点各自拉取词典，需确保 JSON 格式的远程词典在所有节点上可达。
- 词典文件必须 UTF-8 编码，且每行一个词。

## 拼音分词

### Pinyin Analysis Plugin

**概念定义**

Pinyin Analysis Plugin 是 Elasticsearch 拼音分析插件，将汉字转换为拼音（全拼、首字母等），支持拼音搜索——用户输入拼音即可匹配中文内容。ES 8.x 需安装对应版本的 `analysis-pinyin` 插件。

**安装步骤**

```bash
# 1. 在线安装
./bin/elasticsearch-plugin install https://get.infini.cloud/elasticsearch/analysis-pinyin/8.x.x

# 2. 离线安装
./bin/elasticsearch-plugin install file:///path/to/analysis-pinyin-8.x.x.zip

# 3. 重启
systemctl restart elasticsearch

# 4. 验证
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "tokenizer": "standard",
  "filter": ["pinyin"],
  "text": "中国人"
}'
```

**核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `keep_first_letter` | `true` / `false` | `true` | 是否保留首字母（如 `zg`） |
| `keep_separate_first_letter` | `true` / `false` | `false` | 是否分开保留每个字的首字母（如 `z`, `g`） |
| `keep_full_pinyin` | `true` / `false` | `true` | 是否保留全拼（如 `zhong`） |
| `keep_joined_full_pinyin` | `true` / `false` | `false` | 是否保留连写全拼（如 `zhongguo`） |
| `keep_original` | `true` / `false` | `false` | 是否保留原始中文词项 |
| `keep_none_chinese` | `true` / `false` | `true` | 是否保留非中文字符 |
| `keep_none_chinese_in_joined_full_pinyin` | `true` / `false` | `false` | 连写全拼中是否保留非中文字符 |
| `limit_first_letter_length` | 正整数 | 16 | 首字母结果最大长度 |
| `lowercase` | `true` / `false` | `true` | 是否小写化拼音 |
| `remove_duplicated_term` | `true` / `false` | `false` | 是否移除重复词项 |

**REST API 示例**

```bash
# 1. 创建带拼音分析的索引
curl -X PUT "localhost:9200/products" -H "Content-Type: application/json" -d '{
  "settings": {
    "analysis": {
      "analyzer": {
        "pinyin_analyzer": {
          "tokenizer": "ik_smart",
          "filter": ["pinyin_filter"]
        }
      },
      "filter": {
        "pinyin_filter": {
          "type": "pinyin",
          "keep_first_letter": true,
          "keep_full_pinyin": true,
          "keep_joined_full_pinyin": true,
          "keep_original": true,
          "remove_duplicated_term": true,
          "lowercase": true
        }
      }
    }
  },
  "mappings": {
    "properties": {
      "name": {
        "type": "text",
        "analyzer": "ik_max_word",
        "search_analyzer": "ik_smart",
        "fields": {
          "pinyin": {
            "type": "text",
            "analyzer": "pinyin_analyzer",
            "search_analyzer": "standard"
          }
        }
      }
    }
  }
}'

# 2. 测试拼音分析
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "pinyin_analyzer",
  "text": "中国人"
}'
```

**注意事项**

- `keep_original: true` 保留原始中文词项，使得中文和拼音均可搜索，是最常用的配置。
- `keep_joined_full_pinyin: true` 生成 `"zhongguoren"`，便于用户输入连续拼音时匹配。
- 拼音分析器应作为子字段（multi-field）使用，主字段保留原始分词，拼音字段提供拼音搜索能力。
- 拼音字段搜索时建议使用 `standard` 分析器，避免再次生成拼音词项。

### 拼音搜索配置

**概念定义**

拼音搜索配置是指将拼音分析器与中文分词器结合的完整策略，使得用户输入拼音（全拼、首字母、混合）时能正确匹配中文内容，同时不影响中文关键词搜索的精度。

**推荐配置策略**

```bash
curl -X PUT "localhost:9200/products" -H "Content-Type: application/json" -d '{
  "settings": {
    "analysis": {
      "analyzer": {
        "ik_pinyin_analyzer": {
          "type": "custom",
          "tokenizer": "ik_smart",
          "filter": ["pinyin_filter", "lowercase"]
        }
      },
      "filter": {
        "pinyin_filter": {
          "type": "pinyin",
          "keep_first_letter": true,
          "keep_full_pinyin": true,
          "keep_joined_full_pinyin": true,
          "keep_original": true,
          "keep_none_chinese": true,
          "lowercase": true,
          "remove_duplicated_term": true
        }
      }
    }
  },
  "mappings": {
    "properties": {
      "name": {
        "type": "text",
        "analyzer": "ik_max_word",
        "search_analyzer": "ik_smart",
        "fields": {
          "pinyin": {
            "type": "text",
            "analyzer": "ik_pinyin_analyzer",
            "search_analyzer": "standard"
          }
        }
      }
    }
  }
}'

# 拼音搜索（搜索时使用标准分析器，防止二次拼音转换）
curl -X POST "localhost:9200/products/_search" -H "Content-Type: application/json" -d '{
  "query": {
    "multi_match": {
      "query": "zhongguo",
      "fields": ["name", "name.pinyin^2"]
    }
  }
}'
```

**搜索场景矩阵**

| 用户输入 | 查询字段 | 分析器 | 说明 |
|---|---|---|---|
| `中国` | `name` | `ik_smart` | 中文搜索，走主字段 |
| `zhongguo` | `name.pinyin` | `standard` | 全拼搜索，走拼音字段 |
| `zg` | `name.pinyin` | `standard` | 首字母搜索，走拼音字段 |
| `zhong guo` | `name.pinyin` | `standard` | 空格分隔全拼，走拼音字段 |
| `中国 ren` | `name` + `name.pinyin` | `ik_smart` + `standard` | 中英混合，multi_match 跨字段 |

**注意事项**

- 拼音字段的 `search_analyzer` 必须与索引时分析器不同，否则用户输入的拼音会被二次转换为拼音，导致匹配失败。
- 拼音字段的权重（`^2`）应高于主字段，使得拼音精确匹配时排序靠前。
- `keep_original: true` 是关键配置，缺省后将无法通过中文搜索拼音字段。
- 拼音搜索会产生大量词项，索引体积会显著增加（约 2-3 倍），需权衡存储成本。

## 同义词

### synonym Token Filter

**概念定义**

`synonym` Token Filter 在分词后对词项进行同义词替换，将同义词映射为同一词项，使搜索时不同表述能匹配相同内容。支持自定义同义词规则文件或内联规则。

**核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `synonyms` | 同义词规则数组 | 无 | 内联同义词规则 |
| `synonyms_path` | 文件路径 | 无 | 外部同义词文件（相对于 config 目录） |
| `synonyms_set` | 同义词集名称 | 无 | 8.10+ 动态同义词集 |
| `format` | `solr` / `wordnet` | `solr` | 同义词规则格式 |
| `expand` | `true` / `false` | `true` | 是否展开同义词组 |
| `lenient` | `true` / `false` | `false` | 是否忽略解析错误 |

**同义词规则格式（Solr 格式）**

```
# 1. 显式映射（左侧替换为右侧，不可逆）
elasticsearch, es => elasticsearch

# 2. 等价同义词组（双向展开）
elasticsearch, es, elk

# 3. 多词同义词
elastic search, es, elasticsearch
```

**REST API 示例**

```bash
# 1. 内联同义词
curl -X PUT "localhost:9200/articles" -H "Content-Type: application/json" -d '{
  "settings": {
    "analysis": {
      "filter": {
        "my_synonym": {
          "type": "synonym",
          "synonyms": [
            "elasticsearch, es => elasticsearch",
            "快速, 迅速, 快捷",
            "中国, 中华人民共和国, china"
          ]
        }
      },
      "analyzer": {
        "synonym_analyzer": {
          "tokenizer": "ik_smart",
          "filter": ["my_synonym"]
        }
      }
    }
  },
  "mappings": {
    "properties": {
      "title": {
        "type": "text",
        "analyzer": "synonym_analyzer"
      }
    }
  }
}'

# 2. 外部同义词文件
curl -X PUT "localhost:9200/articles" -H "Content-Type: application/json" -d '{
  "settings": {
    "analysis": {
      "filter": {
        "my_synonym": {
          "type": "synonym",
          "synonyms_path": "analysis/synonyms.txt",
          "format": "solr",
          "expand": true
        }
      },
      "analyzer": {
        "synonym_analyzer": {
          "tokenizer": "ik_smart",
          "filter": ["my_synonym"]
        }
      }
    }
  }
}'

# 3. 测试同义词效果
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "synonym_analyzer",
  "text": "快速搜索"
}'
```

**注意事项**

- `expand: true`（默认）时，等价同义词组中所有词项两两互通；`expand: false` 时，仅第一个词项被展开。
- 显式映射（`=>`）不可逆：`a, b => c` 表示搜索 `a` 或 `b` 时匹配 `c`，但搜索 `c` 时不会匹配 `a` 或 `b`。
- 同义词 Filter 在分词后执行，因此中文场景需先确保 IK 分词正确。
- 外部同义词文件的路径相对于 ES `config` 目录，集群环境下每个节点都需要该文件。

### synonym_graph Token Filter

**概念定义**

`synonym_graph` 是 `synonym` 的升级版，支持多词同义词的正确位置偏移处理，生成同义词图谱（Token Graph），确保 `match_phrase` 查询对多词同义词的准确性。ES 8.x 推荐使用 `synonym_graph` 替代 `synonym`。

**synonym vs synonym_graph 差异**

| 特性 | synonym | synonym_graph |
|---|---|---|
| 单词同义词 | 正确 | 正确 |
| 多词同义词 | 可能产生错误偏移 | 正确保留位置关系 |
| match_phrase 查询 | 可能不准确 | 准确 |
| 索引体积 | 较小 | 略大 |

**核心参数**

| 参数 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| `synonyms` | 同义词规则数组 | 无 | 内联规则 |
| `synonyms_path` | 文件路径 | 无 | 外部规则文件 |
| `synonyms_set` | 同义词集名称 | 无 | 8.10+ 动态同义词集 |
| `format` | `solr` / `wordnet` | `solr` | 规则格式 |
| `expand` | `true` / `false` | `true` | 是否展开 |
| `lenient` | `true` / `false` | `false` | 是否忽略错误 |
| `updateable` | `true` / `false` | `false` | 是否允许动态更新（8.10+） |

**REST API 示例**

```bash
curl -X PUT "localhost:9200/articles" -H "Content-Type: application/json" -d '{
  "settings": {
    "analysis": {
      "filter": {
        "my_synonym_graph": {
          "type": "synonym_graph",
          "synonyms": [
            "elasticsearch, es",
            "elastic search, es",
            "中华人民共和国, 中国, china"
          ]
        }
      },
      "analyzer": {
        "synonym_graph_analyzer": {
          "tokenizer": "ik_smart",
          "filter": ["my_synonym_graph"]
        }
      }
    }
  }
}'

# 测试多词同义词（match_phrase 准确性）
curl -X POST "localhost:9200/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "synonym_graph_analyzer",
  "text": "elastic search"
}'
```

**注意事项**

- 多词同义词规则（如 `elastic search, es`）在 `synonym` 中可能导致 `match_phrase` 查询匹配错误，`synonym_graph` 解决了此问题。
- `synonym_graph` 只能用于搜索时分析器，若用于索引时可能导致 `match_phrase` 行为异常（通常建议仅搜索时使用）。
- 8.10+ 支持 `updateable: true`，配合动态同义词集实现热更新。

### 动态同义词（8.10+）

**概念定义**

ES 8.10+ 引入动态同义词（Synonyms API），允许通过 REST API 动态管理同义词集，无需重启节点或修改配置文件，热更新即时生效。同义词集存储在 `.synonyms` 系统索引中。

**核心 API**

```bash
# 1. 创建同义词集
curl -X PUT "localhost:9200/_synonyms/my-synonyms" -H "Content-Type: application/json" -d '{
  "synonyms_set": [
    { "id": "syn-1", "synonyms": "elasticsearch, es => elasticsearch" },
    { "id": "syn-2", "synonyms": "快速, 迅速, 快捷" },
    { "id": "syn-3", "synonyms": "中国, 中华人民共和国, china" }
  ]
}'

# 2. 查看同义词集
curl -X GET "localhost:9200/_synonyms/my-synonyms?pretty"

# 3. 列出所有同义词集
curl -X GET "localhost:9200/_synonyms?pretty"

# 4. 更新同义词集（全量替换）
curl -X PUT "localhost:9200/_synonyms/my-synonyms" -H "Content-Type: application/json" -d '{
  "synonyms_set": [
    { "id": "syn-1", "synonyms": "elasticsearch, es" },
    { "id": "syn-2", "synonyms": "快速, 迅速, 快捷, 高效" },
    { "id": "syn-3", "synonyms": "中国, 中华人民共和国" }
  ]
}'

# 5. 删除同义词集
curl -X DELETE "localhost:9200/_synonyms/my-synonyms"

# 6. 删除同义词集中的单条规则
curl -X DELETE "localhost:9200/_synonyms/my-synonyms/syn-1"
```

**在索引中使用动态同义词集**

```bash
curl -X PUT "localhost:9200/articles" -H "Content-Type: application/json" -d '{
  "settings": {
    "analysis": {
      "filter": {
        "my_synonyms": {
          "type": "synonym_graph",
          "synonyms_set": "my-synonyms",
          "updateable": true
        }
      },
      "analyzer": {
        "synonym_analyzer": {
          "tokenizer": "ik_smart",
          "filter": ["my_synonyms"]
        }
      }
    }
  },
  "mappings": {
    "properties": {
      "title": {
        "type": "text",
        "analyzer": "synonym_analyzer"
      }
    }
  }
}'
```

**注意事项**

- 动态同义词集需要 `synonyms_set` 参数（非 `synonyms` 或 `synonyms_path`），且 Filter 必须设置 `updateable: true`。
- 同义词规则更新后，已索引的文档不会自动重建，需执行 `_update_by_query` 或 Reindex 使已有数据生效。
- 同义词集存储在 `.synonyms` 索引中，建议配置该索引的副本数以防数据丢失。
- 集群环境下，同义词集自动同步到所有节点，无需手动分发。
- 仅 `synonym_graph` 支持动态同义词集，`synonym` 不支持。

## 自定义 Analyzer

### 组合 Tokenizer 与 Token Filter

**概念定义**

自定义 Analyzer 允许将任意 Tokenizer 与 Token Filter 组合，构建满足特定业务需求的分词流水线。一个 Analyzer 由以下组件构成：零到多个 Character Filter、一个 Tokenizer、零到多个 Token Filter。

**Pipeline 执行顺序**

```
原始文本 → Character Filter(s) → Tokenizer → Token Filter(s) → 词项流
```

**REST API 示例**

```bash
# 1. 综合自定义 Analyzer
curl -X PUT "localhost:9200/my_index" -H "Content-Type: application/json" -d '{
  "settings": {
    "analysis": {
      "char_filter": {
        "remove_emoji": {
          "type": "pattern_replace",
          "pattern": "[\\uD800-\\uDBFF][\\uDC00-\\uDFFF]",
          "replacement": ""
        },
        "normalize_symbols": {
          "type": "mapping",
          "mappings": ["& => and", "@ => at"]
        }
      },
      "tokenizer": {
        "my_tokenizer": {
          "type": "standard",
          "max_token_length": 50
        }
      },
      "filter": {
        "my_stop": {
          "type": "stop",
          "stopwords": ["the", "a", "an", "is", "are"]
        },
        "my_stemmer": {
          "type": "stemmer",
          "language": "english"
        },
        "my_length": {
          "type": "length",
          "min": 2
        }
      },
      "analyzer": {
        "my_custom_analyzer": {
          "type": "custom",
          "char_filter": ["remove_emoji", "normalize_symbols"],
          "tokenizer": "my_tokenizer",
          "filter": ["lowercase", "my_stop", "my_stemmer", "my_length"]
        }
      }
    }
  }
}'

# 2. 测试自定义 Analyzer
curl -X POST "localhost:9200/my_index/_analyze" -H "Content-Type: application/json" -d '{
  "analyzer": "my_custom_analyzer",
  "text": "The Quick Brown Foxes & Rabbits are jumping 🦊"
}'
```

**注意事项**

- Filter 执行顺序至关重要：`lowercase` 应在 `stop` 之前，`stemmer` 应在 `stop` 之后。
- `length` Filter 放在最后，避免截断影响其他 Filter 的处理。
- 建议在创建索引前通过 `_analyze` API 充分测试自定义 Analyzer 效果。
- 每个 Filter 的增删改都会影响最终词项流，可通过 `explain: true` 逐步调试。

### 多字段分词策略

**概念定义**

多字段分词策略（Multi-field）是为同一字段配置多个子字段（sub-field），每个子字段使用不同的分析器，实现"一次写入，多种搜索"。典型场景：产品名称需要中文分词、拼音搜索、精确匹配三合一。

**REST API 示例**

```bash
curl -X PUT "localhost:9200/products" -H "Content-Type: application/json" -d '{
  "settings": {
    "analysis": {
      "analyzer": {
        "pinyin_analyzer": {
          "type": "custom",
          "tokenizer": "ik_smart",
          "filter": ["pinyin_filter"]
        }
      },
      "filter": {
        "pinyin_filter": {
          "type": "pinyin",
          "keep_first_letter": true,
          "keep_full_pinyin": true,
          "keep_joined_full_pinyin": true,
          "keep_original": true,
          "lowercase": true
        }
      }
    }
  },
  "mappings": {
    "properties": {
      "name": {
        "type": "text",
        "analyzer": "ik_max_word",
        "search_analyzer": "ik_smart",
        "fields": {
          "raw": {
            "type": "keyword"
          },
          "pinyin": {
            "type": "text",
            "analyzer": "pinyin_analyzer",
            "search_analyzer": "standard"
          },
          "english": {
            "type": "text",
            "analyzer": "english"
          },
          "edge_ngram": {
            "type": "text",
            "analyzer": "autocomplete_analyzer"
          }
        }
      }
    }
  }
}'

# 多字段搜索（权重策略）
curl -X POST "localhost:9200/products/_search" -H "Content-Type: application/json" -d '{
  "query": {
    "multi_match": {
      "query": "华为手机",
      "fields": [
        "name^3",
        "name.pinyin^2",
        "name.english"
      ],
      "type": "best_fields"
    }
  }
}'
```

**字段用途矩阵**

| 子字段 | 类型 | 分析器 | 用途 |
|---|---|---|---|
| `name`（主字段） | `text` | `ik_max_word` / `ik_smart` | 中文全文搜索 |
| `name.raw` | `keyword` | 无 | 精确匹配、聚合、排序 |
| `name.pinyin` | `text` | `pinyin_analyzer` / `standard` | 拼音搜索 |
| `name.english` | `text` | `english` | 英文词干搜索 |
| `name.edge_ngram` | `text` | `autocomplete` | 自动补全 |

**注意事项**

- 子字段不占用额外磁盘空间（共享 `_source`），但每个子字段的倒排索引独立存储。
- 子字段过多会增加索引体积和写入延迟，建议控制在 5 个以内。
- 搜索时通过 `multi_match` 的 `fields` 权重调控不同字段的匹配优先级。
- `multi_match` 的 `type: best_fields` 取最高分字段，`type: most_fields` 累加所有字段得分。

### 索引时与搜索时分析器分离

**概念定义**

索引时分析器（`analyzer`）与搜索时分析器（`search_analyzer`）分离，允许写入时使用细粒度分词（提高召回率），查询时使用粗粒度分词（提高精度），是 Elasticsearch 推荐的高级搜索优化策略。

**核心原理**

```
写入流程: 文档内容 → analyzer → 词项 → 倒排索引
查询流程: 查询关键词 → search_analyzer → 词项 → 倒排索引匹配
```

**典型组合**

| 场景 | 索引时（analyzer） | 搜索时（search_analyzer） | 效果 |
|---|---|---|---|
| 中文搜索 | `ik_max_word` | `ik_smart` | 索引穷举词项，搜索精准匹配 |
| 英文搜索 | `english`（含词干提取） | `standard` | 索引时词干化，搜索时不变 |
| 拼音搜索 | `pinyin_analyzer` | `standard` | 索引时生成拼音，搜索时直接匹配 |
| 同义词 | `standard` | `synonym_graph` | 仅搜索时展开同义词，避免索引膨胀 |
| N-gram | `edge_ngram` | `standard` | 索引时生成前缀，搜索时精确匹配前缀 |

**REST API 示例**

```bash
# 1. 中文搜索：索引细粒度，搜索粗粒度
curl -X PUT "localhost:9200/articles" -H "Content-Type: application/json" -d '{
  "mappings": {
    "properties": {
      "title": {
        "type": "text",
        "analyzer": "ik_max_word",
        "search_analyzer": "ik_smart"
      }
    }
  }
}'

# 2. 同义词搜索：仅搜索时展开同义词
curl -X PUT "localhost:9200/articles" -H "Content-Type: application/json" -d '{
  "settings": {
    "analysis": {
      "filter": {
        "my_synonym_graph": {
          "type": "synonym_graph",
          "synonyms": ["elasticsearch, es", "快速, 迅速"]
        }
      },
      "analyzer": {
        "search_synonym": {
          "type": "custom",
          "tokenizer": "standard",
          "filter": ["lowercase", "my_synonym_graph"]
        }
      }
    }
  },
  "mappings": {
    "properties": {
      "content": {
        "type": "text",
        "analyzer": "standard",
        "search_analyzer": "search_synonym"
      }
    }
  }
}'

# 3. N-gram 自动补全
curl -X PUT "localhost:9200/suggestions" -H "Content-Type: application/json" -d '{
  "settings": {
    "analysis": {
      "filter": {
        "edge_ngram_filter": {
          "type": "edge_ngram",
          "min_gram": 1,
          "max_gram": 20
        }
      },
      "analyzer": {
        "autocomplete_index": {
          "type": "custom",
          "tokenizer": "standard",
          "filter": ["lowercase", "edge_ngram_filter"]
        },
        "autocomplete_search": {
          "type": "custom",
          "tokenizer": "standard",
          "filter": ["lowercase"]
        }
      }
    }
  },
  "mappings": {
    "properties": {
      "suggestion": {
        "type": "text",
        "analyzer": "autocomplete_index",
        "search_analyzer": "autocomplete_search"
      }
    }
  }
}'
```

**注意事项**

- 若未指定 `search_analyzer`，默认使用 `analyzer` 的值。
- 同义词建议仅在搜索时展开（`search_analyzer` 包含 synonym_graph），索引时展开会导致索引膨胀且无法动态更新同义词。
- 索引时 `analyzer` 与搜索时 `search_analyzer` 必须产生兼容的词项格式，否则无法匹配。
- 分离策略的核心原则：索引时"宁可多分"，搜索时"宁可少分"。
