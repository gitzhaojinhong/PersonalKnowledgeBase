# 图数据库核心概念

## 属性图模型

Neo4j 采用属性图模型（Property Graph Model）作为核心数据模型，由节点、关系、属性和标签四种基本元素构成。属性图用节点表示实体，用关系表示实体间的关联，两者均可携带键值对属性。

### 节点

图中的基本数据单元，表示一个离散的实体对象（如人、公司、账户）。每个节点可以包含零个或多个属性以及零个或多个标签。

```cypher
CREATE (:Person:Actor {name: 'Tom Hanks', born: 1956})
```

### 关系

连接两个节点的有向边，表示实体之间的语义关联。每条关系必须有一个类型（如 `ACTED_IN`、`KNOWS`），且关系本身可以携带属性。关系始终有方向，但查询时可以忽略方向。

```cypher
CREATE ()-[:ACTED_IN {roles: ['Forrest'], performance: 5}]->()
```

### 属性

以键值对形式存储的数据，同时附加在节点和关系上。属性值可以是字符串、数值、布尔值、列表、时间类型等。Neo4j 对属性数量没有硬性限制，但建议将大体积数据存储为独立节点。

```cypher
MATCH (p:Person {name: 'Tom Hanks'})
SET p.birthPlace = 'Concord, California',
    p.oscarWins = 2
```

### 标签

一组节点的分类标记，用于将节点分组为集合。一个节点可以有零个或多个标签，标签在查询时用于过滤和模式匹配。标签类似于关系型数据库中的表名，但一个节点可以同时属于多个"表"。

```cypher
MATCH (p:Person:Actor:Producer)
RETURN p.name
```

### 属性图 vs RDF 三元组

属性图拥有内部标识符（节点 ID），关系是数据库中的一等公民。RDF 三元组（主语-谓语-宾语）无内部标识符，所有内容均以全局唯一 URI 标识。属性图更适合需要高性能遍历和复杂关系建模的场景。

## 免索引邻接

Neo4j 的核心性能优势来自免索引邻接（Index-Free Adjacency）。每个节点直接维护指向其邻居关系链表的物理指针，遍历时无需通过全局索引查找，时间复杂度为 O(1)。这意味着无论图规模多大，从一个节点到其邻居的跳转成本恒定。

在关系型数据库中，关联查询需要 JOIN 操作，复杂度随数据量增长呈 O(log n) 甚至 O(n)。图数据库的这一特性使其在深度关联查询场景中表现优异。

## 图数据库 vs 关系型数据库

### 关联查询性能

关系型数据库使用外键和 JOIN 实现关联查询，表越大、层数越深，JOIN 成本越高。图数据库利用免索引邻接，遍历成本与总数据量无关，仅与遍历路径上的节点数相关。

| 场景 | 关系型数据库 | Neo4j 图数据库 |
|------|------------|---------------|
| 单层关联查询 | 索引查找，性能中等 | 指针遍历，O(1) |
| 3-5 层深度关联 | 多次 JOIN，性能显著下降 | 恒定跳转成本 |
| 实时推荐（N 层扩展） | 不可行 | 毫秒级响应 |

### 模型灵活性

关系型数据库需要预先定义 Schema（表结构），变更成本高。Neo4j 是 Schema-optional 的：节点可以动态添加标签和属性，关系也可以在运行时灵活创建。这种灵活性特别适合业务模型快速迭代的场景。

### 适用场景

- **图数据库优先**：社交网络、推荐系统、欺诈检测、知识图谱、身份与访问管理、网络与 IT 运维、供应链管理
- **关系型数据库优先**：财务报表、订单管理、日志存储、数据仓库聚合分析
- **混合使用**：订单用关系型数据库，用户画像和推荐用图数据库

## 路径与遍历

### 路径

节点和关系的交替序列，从一个起始节点出发，沿关系方向到达目标节点。路径是图查询的基本结果形式。

### 变长遍历

变长路径模式支持指定跳数范围，实现多跳关系查询。使用 `*` 语法定义最小和最大跳数。

```cypher
MATCH path = (p:Person {name: 'Tom Hanks'})-[:ACTED_IN*1..3]-(other:Person)
RETURN path
```

### 遍历方向

关系方向（`->`、`<-`、`--`）可以灵活指定。无向查询忽略关系方向，返回所有匹配路径。

```cypher
MATCH (a)-[:KNOWS]-(b)
RETURN a.name, b.name
```

## 图论基础

### 有向图

边具有方向性的图。Neo4j 中的关系默认是有向的，查询时可通过 `-[r]->` 或 `<-[r]-` 指定方向。

### 无向图

边无方向性的图。在 Neo4j 中通过 `--` 或 `-[r]-` 实现无向查询。

### 加权图

边带权重的图。Neo4j 中通过在关系上存储属性（如 `distance`、`cost`、`weight`）来实现加权，图算法（如 Dijkstra、PageRank）可直接使用这些属性。

```cypher
CREATE (a:City {name: '北京'})-[:FLIGHT {distance: 1200}]->(b:City {name: '上海'})
```

### 属性图

顶点和边都可携带属性的图模型，是 Neo4j 的底层数据结构。属性图是图论中"标记图"的推广，支持丰富的数据建模。

## Bolt 协议

### URI Scheme

Bolt 是 Neo4j 自研的二进制网络协议，用于客户端与数据库服务器的通信。URI 格式决定驱动类型：

| URI Scheme | 驱动类型 |
|------------|---------|
| `bolt://` | 直连驱动：直接连接指定主机和端口 |
| `neo4j://` | 路由驱动：自动发现集群成员并路由会话 |
| `bolt+s://` | 加密直连 |
| `neo4j+s://` | 加密路由 |

### 序列化格式

Bolt 采用 PackStream 二进制序列化格式，比 JSON 更紧凑高效。支持流式传输，适合大量数据的逐条消费。

### 连接过程

客户端通过 Bolt 握手建立连接，包括协议版本协商、认证（用户名/密码、Kerberos、SSO）、连接初始化。连接建立后，通过 Session 管理事务生命周期。

## ACID 事务

### 原子性

一个事务内的所有操作要么全部成功，要么全部失败回滚。Neo4j 通过 Write-Ahead Logging（WAL）保证原子性。

### 一致性

事务完成后，数据库从一个一致状态过渡到另一个一致状态。约束（如唯一性约束）在事务提交前验证。

### 隔离性

Neo4j 默认使用读已提交（Read Committed）隔离级别。事务内部可以看到自己未提交的修改，但其他事务看不到。企业版支持可序列化隔离。

### 持久性

已提交的事务数据永久保存，即使系统崩溃。通过事务日志（Transaction Log）和 Checkpoint 机制保证。

## 部署形态

### AuraDB

Neo4j 全托管云服务，在 AWS、GCP、Azure 上运行。提供自动扩缩容、备份、监控和安全性。分为 AuraDB Free（免费）、AuraDB Professional（生产就绪）和 AuraDB Enterprise（高级安全）三层。

### 社区版

开源免费版本，包含核心图数据库功能、Cypher 查询语言、APOC Core。不支持集群、RBAC、多数据库、热备份等企业特性。适合学习和中小型项目。

### 企业版

商业授权版本，包含集群、RBAC、多数据库、在线备份、子图访问控制、细粒度权限、LDAP/OpenID Connect 集成、因果一致性等企业特性。

### Docker

官方提供 Docker 镜像，社区版和企业版均可通过 Docker 部署。支持通过环境变量配置初始密码和插件。

```shell
docker run -d --name neo4j \
  -p 7474:7474 -p 7687:7687 \
  -e NEO4J_AUTH=neo4j/password \
  neo4j:latest
```

### Kubernetes

Neo4j 提供 Helm Chart 和 Neo4j Operator 用于 Kubernetes 部署。支持集群模式、持久化存储、自动扩缩容和滚动升级。
