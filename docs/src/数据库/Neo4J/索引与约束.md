# 索引与约束

索引加速数据查找，约束保证数据完整性。Neo4j 支持多种索引类型（Range、Text、Point、Full-text、Vector）和约束类型（唯一性、存在性、节点键）。创建约束时，Neo4j 自动创建对应的隐式索引。

## 搜索性能索引

### Range 索引

最常用的索引类型，支持精确匹配、范围查询、前缀搜索。通过 `CREATE INDEX` 创建，适用于数值、字符串和布尔类型。

```cypher
CREATE INDEX person_name FOR (n:Person) ON (n.name)
```

### Text 索引

针对字符串比较优化的索引，支持 `STARTS WITH`、`ENDS WITH`、`CONTAINS` 等字符串谓词。比 Range 索引更适合文本搜索场景。

```cypher
CREATE TEXT INDEX node_text_index_nickname FOR (n:Person) ON (n.nickname)
```

### Point 索引

针对空间坐标点（Point 类型）的索引，支持 `point.distance()` 等空间查询。适用于地理位置搜索场景。

```cypher
CREATE POINT INDEX location_index FOR (n:Venue) ON (n.location)
```

### Token Lookup 索引

自动创建的特殊索引，用于快速查找拥有特定标签的节点。每个标签一个 Token Lookup 索引，由 Neo4j 自动维护。

## 全文索引

### 创建全文索引

基于 Lucene 的全文索引，支持词干分析、模糊搜索、短语匹配等高级文本搜索功能。可跨多个标签和属性创建。

```cypher
CREATE FULLTEXT INDEX namesAndTeams IF NOT EXISTS
FOR (n:Employee|Manager) ON EACH [n.name, n.team]
```

### 查询全文索引

使用 `db.index.fulltext.queryNodes()` 过程查询全文索引，支持 Lucene 查询语法。

```cypher
CALL db.index.fulltext.queryNodes('namesAndTeams', 'engineer~') YIELD node, score
RETURN node.name, score
```

### Lucene 分析器

全文索引默认使用标准分析器，支持 `standard`、`simple`、`whitespace`、`stop`、`keyword` 等分析器。分析器决定文本如何被分词和索引。

### 多标签索引

全文索引可以跨多个标签创建，对一个属性集合进行统一索引，适用于跨实体类型的搜索场景。

## 向量索引

### 向量索引类型

Neo4j 支持向量索引，用于存储和检索高维向量嵌入。向量索引是实现语义搜索和 RAG（检索增强生成）的基础。

### 嵌入向量存储

向量索引存储节点的嵌入向量，每个向量由浮点数数组组成。维度需在创建索引时指定。

```cypher
CREATE VECTOR INDEX moviePlots IF NOT EXISTS
FOR (m:Movie)
ON m.embedding
OPTIONS { indexConfig: {
  `vector.dimensions`: 1536,
  `vector.similarity_function`: 'cosine'
}}
```

### 相似度搜索

使用 `db.index.vector.queryNodes()` 过程执行向量相似度搜索，支持 `cosine` 和 `euclidean` 相似度函数。

```cypher
CALL db.index.vector.queryNodes('moviePlots', 3, $queryEmbedding)
YIELD node, score
RETURN node.title, score
```

## 索引管理

### 创建索引

```cypher
CREATE INDEX [name] IF NOT EXISTS FOR (n:Label) ON (n.property)
```

### 删除索引

```cypher
DROP INDEX index_name
```

### 显示索引

```cypher
SHOW INDEXES
SHOW INDEXES YIELD name, type, labelsOrTypes, properties
```

### 索引命名

建议显式命名索引，便于管理和引用。命名规则：`{label}_{property}_index`。

### IF NOT EXISTS

幂等创建索引，如果索引已存在则不报错。

## 索引提示

### USING INDEX

强制查询计划器使用特定索引，用于性能优化。

```cypher
MATCH (p:Person) USING INDEX p:Person(name)
WHERE p.name = 'Tom Hanks'
RETURN p
```

### USING TEXT INDEX

指定使用 Text 索引进行字符串搜索。

### USING POINT INDEX

指定使用 Point 索引进行空间查询。

### USING FULLTEXT INDEX

指定使用全文索引进行文本搜索。

## 唯一性约束

### 单属性唯一

确保节点属性值在给定标签下唯一，自动创建 Range 索引。

```cypher
CREATE CONSTRAINT book_isbn
FOR (book:Book) REQUIRE book.isbn IS UNIQUE
```

### 复合属性唯一

确保多个属性的组合值唯一，自动创建复合 Range 索引。

```cypher
CREATE CONSTRAINT person_name_born
FOR (p:Person) REQUIRE (p.name, p.born) IS UNIQUE
```

### 约束与索引关系

唯一性约束创建时自动生成对应的 Range 索引。约束是索引的上层语义抽象，索引是约束的物理实现。删除约束后，隐式索引也一并删除。

## 属性存在性约束

### 节点属性存在

确保节点在指定标签下必须包含某个属性。

```cypher
CREATE CONSTRAINT person_name_exists
FOR (p:Person) REQUIRE p.name IS NOT NULL
```

### 关系属性存在

确保关系必须包含某个属性。企业版专属功能。

```cypher
CREATE CONSTRAINT acted_in_roles_exists
FOR ()-[r:ACTED_IN]-() REQUIRE r.roles IS NOT NULL
```

## 节点键约束

### 节点键定义

节点键约束同时要求属性存在且唯一，类似关系型数据库的主键。企业版专属功能。

```cypher
CREATE CONSTRAINT director_imdbId
FOR (director:Director) REQUIRE (director.imdbId) IS NODE KEY
```

### 复合唯一与存在

多属性节点键同时要求所有属性存在且组合唯一。

### 企业版限定

节点键约束和属性存在性约束（关系）仅在企业版中可用。社区版只支持唯一性约束和节点属性存在性约束。

## 约束管理

### 创建约束

```cypher
CREATE CONSTRAINT [name] IF NOT EXISTS FOR (n:Label) REQUIRE n.prop IS UNIQUE
```

### 删除约束

```cypher
DROP CONSTRAINT constraint_name
```

### 显示约束

```cypher
SHOW CONSTRAINTS
```

### 约束命名

建议显式命名约束，命名规则：`{label}_{property}_{constraint_type}`。

### 约束验证

约束在事务提交时验证。如果违反约束，事务将回滚并抛出异常。对于已有数据，创建约束前需要确保数据满足约束条件。

## 索引选择性

### 选择性评估

索引选择性决定了索引的有效性。选择性 = 不同值的数量 / 总节点数。选择性越高（接近 1），索引越有效。选择性低于 0.1 的索引可能不会带来性能提升。

### 复合索引选择性

复合索引的选择性取决于各属性组合的唯一度。创建复合索引时，应将选择性高的属性放在前面。

### 索引统计

Neo4j 自动收集索引统计信息供查询计划器使用。可以通过 `SHOW INDEXES YIELD *` 查看索引的使用情况和统计信息。统计信息在数据变更后自动更新。
