# 集群运维与安全

Neo4j 企业版提供集群部署、高可用、读写分离和安全管控能力。集群通过 RAFT 共识协议保证数据一致性，支持多数据中心部署和灾备。安全方面涵盖认证、RBAC、数据加密和审计日志。

## 集群架构

### Core Server

核心服务器，参与 RAFT 共识组，负责写入操作和 Raft 日志复制。集群至少需要 3 台 Core Server 以保证多数派可用。

### Read Replica

只读副本，不参与 RAFT 共识，仅提供读服务。从 Core Server 异步同步数据，适合读密集型场景的水平扩展。

### RAFT 共识

Neo4j 集群使用 RAFT 协议实现分布式一致性。每个数据库形成独立的 Raft 组，有自己的 Leader。Leader 负责排序写入，Follower 复制 Leader 的状态。

### Leader 选举

当 Leader 不可用时，Raft 组自动发起选举。获得多数票的节点成为新 Leader。Leader 选举期间，数据库短暂不可写但可读。

### 日志复制

写入操作先写入 Leader 的 Raft 日志，然后复制到 Follower。多数 Follower 确认后，Leader 提交写入。这保证了强一致性。

## 因果一致性

### Bookmark 机制

客户端在写入事务后获得一个书签，后续读事务携带书签，确保读到的数据版本包含该写入。书签通过 `ResultSummary.bookmark()` 获取。

### 因果链

书签链形成了因果序：客户端写入 A → 获得书签 B → 用书签 B 读取 → 保证读到写入 A 的结果。书签在集群中传递，保证跨节点的因果一致性。

### 读写一致性

通过 Bookmark 机制，客户端可以保证"读自己的写"。这是最终一致性和强一致性之间的实用平衡。

## 读写分离

### RoutingControl

Java Driver 中的 `AccessMode.READ` 和 `AccessMode.WRITE` 控制会话路由。读操作路由到 Read Replica，写操作路由到 Core Server 的 Leader。

### 路由策略

路由驱动缓存路由表，根据 `AccessMode` 和数据库名选择目标服务器。路由表定期从集群更新，反映集群拓扑变化。

### 负载均衡

读写分离实现读负载均衡：多个 Read Replica 分担读请求。集群自动在 Read Replica 之间分配读请求。

## 多数据中心

### 地理冗余

跨数据中心部署 Core Server，实现地理冗余。每个数据中心可以有混合的 Core Server 和 Read Replica。

### 灾难恢复

当一个数据中心故障时，其他数据中心的 Core Server 如果仍占多数，集群继续正常运行。数据中心间通过安全网络通信。

### 跨集群复制

Neo4j 企业版支持跨集群复制（Cluster-to-Cluster Replication），将一个集群的数据异步复制到另一个集群，用于灾难恢复和跨区域数据分发。

### 多区域路由

客户端驱动的多区域路由，根据延迟和可用性选择最优集群。配合 `neo4j://` 路由 URI 实现。

## 查询性能调优

### EXPLAIN

`EXPLAIN` 前缀查看查询的执行计划而不实际执行，展示计划使用的索引、算子和预估行数。

```cypher
EXPLAIN MATCH (p:Person) WHERE p.name = 'Tom Hanks' RETURN p
```

### PROFILE

`PROFILE` 前缀执行查询并返回实际执行统计，包括每个算子的实际行数、数据库命中次数和内存使用。

```cypher
PROFILE MATCH (p:Person) WHERE p.name = 'Tom Hanks' RETURN p
```

### 查询计划解读

查询计划以树形结构展示执行步骤，从底部到顶部依次执行。关注 `NodeByLabelScan`（全扫描）、`NodeIndexSeek`（索引查找）、`Expand(All)`（关系展开）等算子。

### 算子分析

关键算子：`NodeIndexSeek`（索引查找，高效）、`NodeByLabelScan`（全标签扫描，低效）、`AllNodesScan`（全节点扫描，最差）、`EagerAggregation`（内存聚合）、`CartesianProduct`（笛卡尔积，危险）。

### 查询缓存

Neo4j 默认缓存最近 1000 个查询计划。参数化查询可复用缓存计划，字符串拼接的查询无法复用。查询计划缓存命中率可在 Metrics 中监控。

### 重规划策略

数据统计变化后，查询计划器可能重新规划查询。`Cypher Replan Events` 指标监控重规划频率。频繁重规划时检查数据是否剧烈变化。

### 查询选项

使用 `CYPHER runtime=parallel` 等选项控制查询执行引擎。`CYPHER runtime=slotted` 适用于简单查询，`CYPHER runtime=pipelined` 是默认引擎，`CYPHER runtime=parallel` 适用于大型并行查询。

## 运行时

### Slotted Runtime

基于槽位的执行引擎，为每个算子分配固定槽位（Slots）。开销低，适合简单查询。

### Pipelined Runtime

管道化执行引擎，基于 Morsel 的并行执行。对复杂查询有更好的 CPU 利用率和缓存局部性。Cypher 5 起为默认运行时。

### Parallel Runtime

并行运行时，将查询拆分为多个并行任务。适用于大型聚合和扫描查询。需要 `CYPHER runtime=parallel` 显式启用。

### 运行时选择

简单查询用 Slotted，复杂查询用 Pipelined，大型聚合用 Parallel。Neo4j 自动选择，也可以通过查询选项覆盖。

## 内存配置

### 堆内存

JVM 堆内存，用于查询执行、事务状态、查询缓存等。通过 `server.memory.heap.initial_size` 和 `server.memory.heap.max_size` 配置，建议设为相同值。

```properties
server.memory.heap.initial_size=3G
server.memory.heap.max_size=3G
```

### 页面缓存

磁盘数据的缓存，用于加速读取。通过 `server.memory.pagecache.size` 配置，建议不小于数据目录大小。使用 `neo4j-admin server memory-recommendation` 获取推荐值。

### 事务内存

每个事务的内存预算，控制事务可使用的最大内存。`dbms.tx_state.memory_allocation.max` 配置。超过限制时事务失败。

### 查询内存

单个查询的内存预算，防止查询耗尽数据库内存。通过 `server.memory.query.max_capacity` 和 `server.memory.query.max_per_query` 配置。

## 连接池管理

### 服务端连接池

Neo4j 服务端的 Bolt 连接池，限制并发连接数。`server.bolt.connection_pool.max_size` 控制最大连接数。

### 客户端连接池

Java Driver 端的连接池，通过 `Config` 配置。`withMaxConnectionPoolSize()` 设置最大连接数，`withConnectionAcquisitionTimeout()` 设置获取超时。

### 连接限制

同一客户端 IP 的最大连接数限制，防止单一客户端耗尽连接。

### 连接超时

连接空闲超时、连接生命周期超时、连接获取超时，分别控制连接的回收时机。

## 存储引擎

### 存储格式

Neo4j 使用自研的块存储格式，节点存储、关系存储、属性存储分开存放在不同文件中。通过 `neo4j-admin copy` 可以压缩存储。

### Checkpoint

Checkpoint 将内存中的脏页刷新到磁盘，减少崩溃恢复时间。通过 `server.db.checkpoint.interval` 配置间隔。

### 事务日志

事务日志记录所有已提交事务，用于崩溃恢复和增量备份。日志文件定期轮转和清理。

### 日志清理

`server.db.tx_log.rotation.retention_policy` 控制事务日志保留策略。`keep_all` 保留所有日志，`keep_none` 不保留。

### 空间回收

Neo4j 不会自动回收删除节点和属性占用的空间。使用 `neo4j-admin copy` 压缩数据库，或 `neo4j-admin check` 检查空间使用。

## 备份与恢复

### 在线备份

企业版支持在线备份（`neo4j-admin database backup`），无需停机。备份过程中数据库正常服务。

```shell
neo4j-admin database backup --to-path=/backup neo4j
```

### 离线备份

停机后使用 `neo4j-admin database dump` 导出完整数据库。比在线备份更快，但需要停机。

### 增量备份

`neo4j-admin database aggregate-backup` 合并增量备份和全量备份，减少备份存储空间和时间。

### 时间点恢复

结合全量备份和事务日志，恢复到指定时间点。

### 数据库复制

`neo4j-admin database copy` 复制数据库，用于搭建测试环境或迁移。

## 监控

### Metrics

Neo4j 暴露多种 Metrics，包括事务、查询、内存、磁盘、网络、集群等维度。通过 `server.metrics.enabled` 开启。

```properties
server.metrics.enabled=true
server.metrics.filter=*check_point*,neo4j.page_cache.evictions
```

### Prometheus

Neo4j 原生支持 Prometheus 指标采集，通过 `/metrics` 端点暴露。配置 `server.metrics.prometheus.enabled=true` 启用。

### Grafana

Neo4j 提供官方 Grafana Dashboard，可视化监控指标。包括查询性能、事务吞吐量、页面缓存命中率、集群状态等。

### 查询日志

`dbms.logs.query.enabled` 启用查询日志，记录所有执行查询的详细信息（执行时间、参数、计划）。用于性能审计和问题排查。

### 安全日志

`dbms.logs.security.enabled` 启用安全事件日志，记录认证、授权、权限变更等安全操作。

### 查询管理

`SHOW TRANSACTIONS` 查看运行中的事务，`TERMINATE TRANSACTION` 终止指定事务。用于排查慢查询和锁等待。

### 连接管理

`SHOW USERS` 和 `SHOW ROLES` 管理用户和角色，`SHOW DATABASES` 查看数据库状态。

## 认证

### Native Auth

Neo4j 内置的用户名/密码认证，通过 `CREATE USER` 创建用户，`ALTER USER` 修改密码。

```cypher
CREATE USER alice SET PASSWORD 'secret' CHANGE NOT REQUIRED
```

### LDAP

通过 LDAP 协议集成企业目录服务（如 Active Directory），统一管理用户认证。配置 `dbms.security.authentication_providers=ldap,native`。

### OpenID Connect SSO

支持 OpenID Connect 单点登录（Azure AD、Okta、Keycloak 等）。配置 `dbms.security.authentication_providers=oidc-azure` 和 PKCE 流程。

```properties
dbms.security.authentication_providers=oidc-azure
dbms.security.oidc.azure.display_name=Azure
dbms.security.oidc.azure.auth_flow=pkce
```

### Kerberos

通过 Kerberos 协议实现单点登录，需要 Neo4j Kerberos Add-On。适用于企业内部 Windows 域环境。

### 混合认证

可以同时启用多种认证提供者，如 `ldap,native` 或 `oidc-azure,native`。认证时按配置顺序依次尝试。

### 用户管理

`CREATE USER`、`ALTER USER`、`DROP USER`、`SHOW USERS` 管理用户。`GRANT` 和 `REVOKE` 管理权限。

## RBAC

### 内置角色

Neo4j 提供 `PUBLIC`、`READER`、`EDITOR`、`PUBLISHER`、`ARCHITECT`、`ADMIN` 内置角色，从低到高权限递增。

### 自定义角色

`CREATE ROLE` 创建自定义角色，`GRANT ROLE` 将角色授予用户。支持角色继承。

```cypher
CREATE ROLE analyst
GRANT ROLE analyst TO alice
```

### 权限管理

`GRANT` 授予权限（`ACCESS`、`READ`、`WRITE`、`CREATE`、`DELETE`、`MATCH` 等），`REVOKE` 撤销权限。支持 `DENY` 显式拒绝。

```cypher
GRANT MATCH {*} ON GRAPH neo4j TO analyst
GRANT READ {*} ON GRAPH neo4j TO analyst
```

### 子图访问控制

企业版支持的细粒度权限，限制用户只能访问特定标签和关系类型的子图（如只允许访问 `:Employee` 节点）。

```cypher
GRANT READ {*} ON GRAPH neo4j NODES Employee TO hr_user
```

### 细粒度权限

属性级访问控制，限制用户只能读取或修改特定属性。通过 `GRANT SET PROPERTY {name, email}` 等语法实现。

## 数据加密

### TLS 传输加密

客户端与服务器之间的 Bolt 通信通过 TLS 加密。配置 `dbms.connector.bolt.tls_level` 控制加密级别（`REQUIRED`、`OPTIONAL`、`DISABLED`）。

### 集群内加密

集群成员之间的 Raft 通信和事务日志复制通过 TLS 加密。配置 `server.cluster.system_database.bolt.tls_level`。

### 静态加密

磁盘上的数据文件加密，保护数据在存储层的安全。企业版专属功能，需要配置加密密钥。

### 证书管理

TLS 证书的生成、分发和轮换。Neo4j 支持自签名证书和 CA 签发证书。证书通过 `dbms.ssl.policy.bolt.private_key` 和 `public_certificate` 配置。

## 审计日志

### 安全事件

审计日志记录所有安全相关事件：登录/登出、权限变更、用户管理、角色变更、数据访问等。通过 `dbms.logs.security.enabled` 启用。

### 审计记录

每条审计记录包含时间戳、操作类型、用户、客户端地址、执行语句等信息。日志格式可配置为 JSON 或 CSV。

### 合规要求

审计日志满足 SOC 2、HIPAA、GDPR 等合规要求。日志可导出到外部 SIEM 系统（如 Splunk、ELK）。
